# スキルの書き方

スキルを書く人向けの決まり。スキルを使う人向けの案内はリポジトリ直下の AGENTS.md にある。

## 置き場所

1 スキル 1 ディレクトリ。名前は TODO.md の名前と同じにする。

```
<skill>/
  SKILL.md       手順。frontmatter に name と description
  references/    手順の中で必要になったときに読む資料
  assets/        出力のひな形など
  scripts/       (必要になったら) 手順で使うスクリプトとそのテスト
```

## 後で書く

- SKILL.md の frontmatter の description の書き方 (いつ発火させたいかを書く)
- SKILL.md の冒頭に置く reference の表 (reference / 読むとき / 中身)
- 事実の置き場所: サービスやライブラリごとの事実は `references/` に 1 対象 1 ファイルで置き、SKILL.md には一般的な手順だけを書く
- 事実は確かめてから書く: 価格、無料枠、規約、対応機能は公式ページで確かめ、確かめた日と版を書く。確かめていないことは「未確認」と書く
- ライセンス上の注意: GPL / LGPL / AGPL などのコピーレフト、OSI 非承認、UNLICENSED、データの ODbL などの継承条件があるものは、組み込み、改変、配布、SaaS 提供のそれぞれで何が求められるかを書く
- 公開リポジトリに書かないもの: 社内の数値、取引先との契約条件、非公開の価格
- 文体: 日本語、em ダッシュを使わない、段落内で改行しない
- スキルを足す、消す、名前を変えたら TODO.md を直す
- 利害関係の開示: 作者と関係のある製品を比べるスキルでは、SKILL.md の「注意」に 1 行だけ置き、文面はリポジトリ直下の AGENTS.md と揃える。スキルは単独でも入れられるので SKILL.md からは消さないが、同じスキルの reference には重ねて書かない (provider の reference の「執筆上の注意」は書き方の決まりなので別)
