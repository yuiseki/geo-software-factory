# 比較の軸 (地図タイル・地図データの供給元)

タイルサービスと自前配信を同じ軸で並べるための手順。比較を始める前に読む。各候補の事実は `providers/` などの各 reference にあり、この文書には軸と判定の手順だけを書く。例として挙げる事実は、各 reference に 2026-11-10 時点で書かれていたもの。

## 進め方

1. 要件 (プロダクト概要) から、足切りの条件に当たるものを決める。
2. 足切りで候補を減らす。足切りは「点数を下げる」ではなく「候補から外す」。
3. 残った候補を、評価の軸ごとに比べる。軸の重みは「要件から軸の重みを決める」の表で決める。
4. 費用は「費用の見積もり方」の手順で、規模ごとに出す。
5. 推奨を先に書き、続けて軸と候補ごとの評価を表で示す。確かめられなかった項目は「未確認」のまま表に残し、推測で埋めない。

## 足切りの条件

要件に当てはまるものだけを当てる。1 つでも満たさない候補は外す。

| 条件 | 何を確かめるか | 外れる例 (各 reference の記述) |
|---|---|---|
| 対象地域の法規制 | 対象地域に中国本土や韓国が入るか。入るなら、その地域で使えるサービスに限られる | 中国本土は GCJ-02 の認可データが要る ([regional/china](regional/china.md))。韓国は地図データの国外持ち出しが規制されている ([regional/korea](regional/korea.md)) |
| 商用利用の可否 | 利用者が営利組織か、収益があるか。無料プランや無料データが非商用に限られていないか | Stadia Maps の Free は非商用で、営利組織の利用は収益がなくても商用とされる ([stadia-maps](providers/stadia-maps.md))。EOX Sentinel-2 cloudless の 2018 年版以降は CC BY-NC-SA ([eox-s2cloudless](imagery/eox-s2cloudless.md)) |
| 公共案件での利用 | 発注者が自治体・政府か。受託開発で納品する構成か | Cesium ion の無料枠は政府案件に使えない ([cesium-ion](3d/cesium-ion.md)) |
| 外部通信の可否 | 閉域網、オフライン、データの国内保持が求められるか | 外部通信が許されないなら、自前配信 ([self-hosting](self-hosting.md)) かオンプレ版のある製品 (MapTiler On-Prem、[maptiler](providers/maptiler.md)) に限られる |
| ライブラリとの組み合わせ | 使いたい描画ライブラリで、そのタイルを表示してよいか | Google のタイルは Google 以外の地図と併用できない ([google-maps](providers/google-maps.md))。Mapbox のタイルはモバイルでは Mapbox の SDK を通してしか使えない ([mapbox](providers/mapbox.md))。Esri の Basemap Styles は Esri のサービスと組み合わせて使う ([esri-arcgis-location-platform](providers/esri-arcgis-location-platform.md)) |
| キャッシュと保存 | タイルを端末やサーバーに保存する必要があるか (オフライン、再配信) | Google の Map Tiles API はキャッシュを許していない ([google-maps](providers/google-maps.md)) |
| データの二次利用 | 地図や画像を解析や機械学習に使うか | Esri World Imagery は解析や AI/ML 学習への利用を規約で禁じている ([esri-world-imagery](imagery/esri-world-imagery.md)) |
| 大量アクセスの許容 | 想定する表示回数が、無償の公開タイルの利用方針に収まるか | tile.openstreetmap.org はアクセスをいつでも止めうると明記している ([tile-openstreetmap-org](providers/tile-openstreetmap-org.md))。本番の主たる供給元にしない |

## 評価の軸

### 1. 費用

「費用の見積もり方」の節で、課金単位と使い方の経路を揃えてから比べる。月額だけでなく、契約形態 (セルフサーブか、見積もり制か、年間契約か、最小契約期間) も並べる。見積もり制のサービスは金額を推測せず「要見積もり」と書く。

### 2. 地図データの詳しさと出どころ

- 出どころ: 自社調査、OSM、公的データ (国土地理院など)、他社からのライセンスのどれか。出どころが同じなら、表示の詳しさは近くなる。
- 国内の詳しさ: 建物の形状、住所・番地、POI、道路の属性、日本語の注記。グローバルなサービスの多くは、国内データの出どころと詳しさを公表していない (Google、TomTom、Esri は reference で「未確認」)。国内の詳しさが要件の中心なら、候補ごとに対象地域の画面を実際に見比べる。
- 公的な正確さ: 行政の図面や防災との整合が要るなら、公的データ (地理院タイル、[gsi-tiles](providers/gsi-tiles.md)) を使うか、公的データを取り込んだスタイル (MapTiler の日本向けスタイル) を候補にする。
- 更新頻度: 新しい道路や施設が載るまでの時間。公表されていないことが多い。

### 3. 機能

ベースマップの描画以外に何が要るかで、候補の価値が変わる。

| 機能 | 確かめること |
|---|---|
| ベクトルタイルとスタイルの編集 | ベクトルタイルを提供しているか、配色や表示する地物を変えられるか |
| 衛星・航空写真 | 解像度、撮影時期、過去画像の有無 (`imagery/` の各 reference) |
| 地形と 3D | 標高タイル、3D 建物、3D Tiles (`3d/` の各 reference) |
| ジオコーディング、ルート検索 | 同じ契約で使えるか、別サービスを組み合わせるか。国内の住所に対応しているか |
| オフライン | 端末への保存が規約と技術の両方で可能か |

### 4. 安定性と運用

- SLA: 多くのサービスはセルフサーブのプランに SLA を付けていない。稼働率の約束がある例は、Esri (月間 99.9%)、MapTiler の Custom (99.9%) などで、上位の契約に限られることが多い。業務システムで SLA が要るなら、どの契約で SLA が付くかを確かめる。
- 運営の継続性: 運営主体 (企業、財団、コミュニティ、個人) と資金源。寄付で運営されるサービス (OpenFreeMap) や、ボランティアで運営されるサーバー (tile.openstreetmap.jp) は、予告なく止まりうる前提で使う。
- 公開の形態: 試験公開や試験運用のものは URL や属性が変わりうる (地理院の最適化ベクトルタイル、PLATEAU の配信)。本番で使うなら、自前に取り込む経路を用意する。
- 障害情報: ステータスページがあるか。

### 5. ライセンスと権利

- 帰属表示: 地図上に何を表示する義務があるか。表示を消せない、または特定の書式が求められることがある。
- データの継承条件: OSM 由来のデータは ODbL。自前で加工して配る場合は、派生データベースの扱いを確かめる ([self-hosting](self-hosting.md) の「ライセンス上の注意」)。
- 自前配信のツールのライセンス: GPL などのコピーレフトのツール (Nominatim、PostGIS、osm2pgsql) を改変して配る場合の義務 ([self-hosting](self-hosting.md))。
- 比較・公表の制限: 契約者が競合製品との比較やベンチマークを公表することを、規約で制限しているサービスがある (TomTom の規約 11.6.10、[tomtom](providers/tomtom.md))。

### 6. 移行のしやすさ

- スタイルの互換: MapLibre Style Spec で書かれたスタイルなら、供給元を替えても描画ライブラリを替えずに済む。独自 SDK でしか表示できないタイルは、供給元を替えるとライブラリも替わる。
- タイルのスキーマ: OpenMapTiles、Shortbread、Protomaps など、スキーマが同じならスタイルを使い回せる。CARTO のベクトル版は 2026-10 に Protomaps スキーマへ移った ([carto-basemaps](providers/carto-basemaps.md))。
- 自前配信への逃げ道: 規模が大きくなったときに自前配信 (PMTiles など) へ移せるか。

### 7. 自前で運用する負担

自前配信は、費用の軸では有利になりやすいが、データの更新、監視、障害対応、帰属表示を自分で引き受ける ([self-hosting](self-hosting.md) の「運用の負担」)。運用体制 (人数、夜間対応の有無) を要件から確かめ、この軸で比べる。

### 8. 窓口とサポート

日本語の窓口、請求書払い、国内法人との契約が要るか。公共案件では、国内の契約主体と請求書払いが要件になることが多い。

## 費用の見積もり方

### 課金単位と経路を先に決める

同じサービスでも、使い方の経路で課金単位が変わる。比較の前に、候補ごとに経路を 1 つ決め、その経路の課金単位を表に書く。2026-11-10 に各社の公式文書で確かめた課金単位は次のとおり。

| 課金単位 | サービスと経路 |
|---|---|
| 地図の表示回数 (地図ロード、セッション、PV) | Google の Maps JavaScript API とモバイル SDK、Mapbox GL JS、MapTiler SDK、Geolonia Maps、ZENRIN Maps API (JS 地図はローダーの読み込みごとに 1 PV)、MapFan API |
| タイルのリクエスト数 | HERE、TomTom、Stadia Maps、CARTO、Azure Maps (15 タイルで 1 トランザクション)、Google の Map Tiles API、Mapbox のタイルを GL JS 以外から使う場合、MapTiler のタイルを MapTiler SDK 以外から使う場合、Esri (タイル方式) |
| MAU | Mapbox のモバイル SDK |
| 時間枠のセッション | Esri (セッション方式、1 セッション最長 12 時間) |
| 課金なし | tile.openstreetmap.org、tile.openstreetmap.jp、OpenFreeMap、地理院タイル、NASA GIBS、PLATEAU |

HERE がタイルのリクエスト数で課金することは、公式文書の一般則 (1 リクエストを 1 トランザクションと数える) からの推定。

### 規模の指標を揃える

規模は「月間の地図表示回数」で揃える。要件からこの数を決め (ページビューのうち地図を開く割合、1 回の訪問で地図を開く回数)、各候補の課金単位に換算する。

- 表示回数で課金される経路: 月間の地図表示回数がそのまま課金単位になる。パンやズームをしても回数は増えない。
- タイル数で課金される経路: 月間の地図表示回数 × 1 回の表示あたりのタイル数。1 回の表示あたりのタイル数は、自分の画面で地図を開き、ふだんの操作 (パンとズームを数回) をしたときのタイルのリクエスト数をブラウザの開発者ツールで数えて決める。測れない段階では 15 タイルを仮置きし、その 2 倍 (30 タイル) でも計算して幅で示す。15 タイルは、Azure Maps と MapFan API が課金の換算に使っている数を借りた仮置きで、実測の値ではない。
- MAU で課金される経路: 月間の利用者数。表示回数とは別に、要件から決める。
- セッションで課金される経路: 利用者が地図を開いている時間の長さで回数が変わる。業務システムのように長時間開いたままの画面では、表示回数より少なくなる。

### 規模ごとに並べる

月 10 万、100 万、1,000 万回の地図表示で、候補ごとの月額を出す。各 reference の概算は経路と仮定がファイルごとに違うので、そのまま並べず、上の手順で計算し直す。計算式と仮定 (経路、1 回の表示あたりのタイル数) を表の下に書く。

### 地図以外の費用

ジオコーディング、ルート検索、衛星画像、3D は別の課金になることが多い。要件に入っていれば、地図の表示とは別に見積もる。自前配信では、タイル生成の計算資源、保存、転送、運用の人件費を足す。

## 要件から軸の重みを決める

プロダクト概要の項目ごとに、効く足切りと、重くする軸を決める。

| 要件 | 足切りに当てる条件 | 重くする軸 |
|---|---|---|
| 個人利用、試作 | 大量アクセスの許容 | 費用 (無料で使えるか) |
| 商用、営利組織 | 商用利用の可否 | 費用、安定性と運用、ライセンスと権利 |
| 自治体・公共の案件 | 公共案件での利用 | 地図データの詳しさと出どころ (公的な正確さ)、窓口とサポート、安定性と運用 |
| 国内が対象で、住所や建物の詳しさが価値の中心 | なし | 地図データの詳しさと出どころ。実画面で見比べる |
| 中国本土、韓国が対象に入る | 対象地域の法規制 | 地図データの詳しさと出どころ |
| 月 100 万回以上の地図表示 | 大量アクセスの許容 | 費用 (課金単位と経路の選び方の影響が大きい)、移行のしやすさ |
| 閉域網、オフライン | 外部通信の可否、キャッシュと保存 | 自前で運用する負担 |
| 衛星画像、3D が要る | データの二次利用 (解析に使うなら) | 機能 |
| 使う描画ライブラリが決まっている | ライブラリとの組み合わせ | 移行のしやすさ |
| SLA が求められる業務システム | なし | 安定性と運用 (SLA の付く契約と費用を合わせて比べる) |

## この文書で扱っていない軸

- タイル配信の速さ (国内からの応答時間、CDN の配置): reference で測っていない。比べるなら、候補ごとに同じ条件で測る。
- アクセシビリティ (配色のコントラスト、文字の大きさ): スタイルの側の問題として、描画ライブラリの比較 (compare-map-library) と合わせて扱う。
