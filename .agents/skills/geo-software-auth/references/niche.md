# 国内や公共の案件で候補になる認証

対象: GビズID、マイナンバーカードによる公的個人認証 (JPKI) とデジタル認証サービス (旧 デジタル認証アプリ)、自治体の LGWAN 環境での認証、providers/ に入れていない国内の認証サービス

## メタ情報

| 項目 | 値 |
|---|---|
| 確かめた日 | 2026-11-11 |

## 概要

国内の公共案件では、汎用の認証サービスのほかに、国が提供する認証基盤 (GビズID、マイナンバーカード) と、自治体の閉域網 (LGWAN) の条件が選択を縛る。GビズID は行政機関等が行政サービスと連携するためのもので、民間のサービスが連携する正式な手続は見つからなかった。マイナンバーカードの本人確認は、デジタル庁のデジタル認証サービスか、主務大臣認定を受けて公的個人認証を直接使う道がある。

## 判断を左右すること

- 利用者が誰か: 事業者が行政に申請する画面なら GビズID が候補になりうるが、連携できるのは行政機関等が提供する行政サービスである (規約第 1 条、第 2 条)。民間の地図 SaaS が直接連携する前提は置かない。
- 本人確認の強さが要るか: 実在の個人であることを確かめる必要があるなら、マイナンバーカードの経路を検討する。ログインのたびに使う認証とは分け、登録時の本人確認にだけ使う設計もある (推測)。
- ネットワーク: LGWAN 接続系から使うなら、外部の管理型認証サービスに届かないことがある (推測)。自前運用の OSS を LGWAN 側に置くか、LGWAN-ASP のサービスを選ぶ。
- 調達の条件: 政府の調達では ISMAP クラウドサービスリストへの登録が求められることがある。各 provider の reference の「公共案件での利用」を見る。

## 手順

1. 案件の利用者 (住民、事業者、自治体職員) と、ネットワーク (インターネット、LGWAN 接続系) を確かめる。
2. 事業者向けの行政サービスなら、発注者 (行政機関等) に GビズID との連携の予定を聞く。連携の申込みは行政機関等が行う (規約の作り。推測)。
3. 個人の本人確認が要るなら、デジタル庁の民間事業者向けページで、デジタル認証サービスの最新の条件を確かめる。
4. LGWAN 接続系から使うなら、発注者に LGWAN-ASP の要否と、J-LIS の登録の条件を確かめる。
5. 汎用の認証サービスを使う部分は、providers/ の reference で比べる。

## 落とし穴

- GビズID の規約は 2025 年 3 月版と 2026 年 7 月版のプライムの規約が公開されている (検索結果から。本文は未確認)。読むときは最新版を使う。
- デジタル庁は民間サービスでの GビズID の活用を実証として進めているとの報道や発表がある (検索結果から。デジタル庁の一次資料は未確認)。正式な制度と取り違えない。
- 「デジタル認証アプリ」は 2026-08-25 から呼称が変わっている。古い資料の名前のまま調べると見落とす。

## ライセンス上の注意

- ここで挙げたものはソフトウェアのライセンスではなく、国の規約と認定の制度で縛られる。GビズID は「GビズID サービス連携 利用規約」、公的個人認証は主務大臣認定の条件に従う。条文の解釈は断定しない。
