# 小さく積む順番

地図アプリ 1 本 (Cloudflare Workers と D1、MapLibre GL JS、PWA) を作ったときの順番を一般化したもの。1 段ごとにテストを先に書き、テスト、型検査、ビルドを通してコミットする。その記録では、次の 1 から 8 までを 22 分で通した。

| 段 | 作るもの | 先に書くテスト |
|---|---|---|
| 1 | 画面に依存しない純粋な関数 (距離、並べ替え、表示用の文言) | 入力と出力の表 |
| 2 | 地図に載せるデータの形と検査 (必須の項目、座標の範囲、出典と帰属表示の有無) | 壊れたデータで検査が落ちること |
| 3 | 端末に溜める仕組み (オフラインでの記録、送信待ちの列) | 送信前に消えないこと、重複しないこと |
| 4 | データの組み立て (出典を固定した取得から、配る形式への変換) | 出典の欠けた行でビルドが落ちること ([data](data.md)) |
| 5 | サーバーの API と保存 (認証、書き込み、読み出し) | 本番と同じ実行環境で、マイグレーションを当てた DB に対して ([testing](testing.md)) |
| 6 | 同期 (送信待ちを送り、サーバーの写しを取り込む) | 衝突したときの勝ち方 (新しいほうが勝つなど)、未来の時刻の扱い |
| 7 | 画面 (一覧、地図、操作) | 表示の組み立ては関数として。画面の通しは [testing](testing.md) の確かめ方で |
| 8 | 公開の準備 (ビルド、README、ライセンス) | ビルドが通ること |

## 地図まわりの順番

- 地図のライブラリは、地図を開いたときだけ読み込む。一覧だけを見る人に重いライブラリを配らない。
- 地図のプロダクトなら、最初に開く画面を地図にする。一覧が先に出ると、地図のカードを押した人が戸惑う。
- 現在地は、ライブラリ標準のコントロール (MapLibre GL JS の GeolocateControl など) を使う。状態の色分けや追従を作り直さない。
- 初めの表示範囲は、場面で変える。旅行中のように現在地が意味を持つときは現在地と対象を、振り返るときは対象の地物だけを収める。
- 小さな地図のカードは操作を無効にし、収める範囲に余白 (fitBounds の padding) を取る。

## 段を飛ばしたくなったら

段を飛ばすと、飛ばした段のテストが無いまま上に積むことになる。急ぐときは、段を飛ばすのではなく、その段の機能を減らす (Should と Could を後ろに回す)。
