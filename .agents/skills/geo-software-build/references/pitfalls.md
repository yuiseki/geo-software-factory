# 実際に踏んだ失敗

地図アプリ 1 本を企画から公開まで通したときに踏んだもの。見つけ方と一緒に置く。

## 配線が無テストで、本番で壊れた

純粋な関数とサーバーの API はテストを先に書いたが、画面の配線 (起動時の同期、認証 SDK の読み込み待ち、一度に 1 つの同期) は無テストで出した。本番で、端末間の設定が同期されなかった。手元の確認は利用者と違う認証の経路で通していたので見えなかった。

- 見つけ方: 配線を依存を差し込めるモジュールに切り出し、時間切れ、トークン待ち、実行中の再要求をテストに書く。通しの確認を利用者と同じ認証の経路で行う ([testing](testing.md))。

## 依頼を読み違えた

「カードにもう少し余白を」を、カードの外側の余白と読んで直したが、意図は地図を収める範囲の余白 (fitBounds の padding) だった。

- 見つけ方: 見た目の依頼は、変える前と後のスクリーンショットを並べて確かめる。夜は聞けないので、昼の擦り合わせで見た目の基準 (参考の画面、数値) をもらっておく。

## 手元の開発サーバーが古いものを配った

`wrangler dev` は、ビルドで静的ファイルが作り直されると、それを配らなくなることがあった (2026-11-12、wrangler 4 系)。

- 見つけ方: ビルドのたびに開発サーバーを立て直す。立て直すときは、プロセス名でなく、自分が起動したプロセスの番号で止める (`pgrep -f` は自分自身のコマンドに一致することがある)。

## ヘッドレスのブラウザで地図が出なかった

ヘッドレスの Chromium に WebGL2 が無く、地図の初期化が失敗した。アプリは「一覧を読み込めませんでした」と出していて、原因がデータの読み込みに見えた。

- 見つけ方: ブラウザのコンソールとネットワークを記録して、どの段で落ちたかを確かめる。ソフトウェアの WebGL を有効にして撮り直す ([testing](testing.md))。アプリのエラーの文言を、本当の原因ごとに分ける。

## 存在しない機能を言った

参考にした地図のサービスが「重なる写真を束にまとめている」と報告したが、実際にはまとめていなかった。

- 見つけ方: 他のサービスの振る舞いを言う前に、画面の要素を数えるなど、測れる形で確かめる。

## 公開の前の履歴に、消したはずの誤記が残っていた

本文から消した誤記が、古いコミットに残っていた。公開の直前に気づき、履歴を書き換えてから公開した。

- 見つけ方: 公開の前に、全履歴に対して、秘密 (鍵、トークン)、手元のパス、誤記として消した文を検索する。履歴を書き換えるときは、先にリポジトリ全体を退避する。
