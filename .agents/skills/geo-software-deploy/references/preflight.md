# 夜に入る前の準備と、直前の確認

## 昼のうちに人間に頼むもの

デプロイに要るもので、人間にしかできないもの。プロダクト概要の「準備したもの」に書いてもらう。

| 種類 | 例 | 確かめ方 (値を出さない) |
|---|---|---|
| アカウントと課金 | ホスティング、DB、認証のプロバイダー、独自ドメインのゾーン | CLI でアカウントの名前が引けること |
| CLI の認証 | デプロイの CLI (wrangler など)、GitHub の CLI | 認証の状態を表示するコマンドが成功すること |
| 鍵と環境変数 | 秘密の鍵の名前と置き場所 | 名前が設定されていること (値は表示しない) |
| 恒久的な許可 | 「この提供元への本番デプロイは確認なしでよい」「追加だけのマイグレーションはよい」 | プロダクト概要とエージェントの設定に書かれていること |
| してはいけない操作 | DB の削除、既存データの上書き、公開範囲の変更、課金の増加 | プロダクト概要に書かれていること |
| 公開の範囲 | 一般公開、限定公開、プレビューまで。リポジトリを公開してよいか | プロダクト概要に書かれていること |

## ブラウザでの認証は昼に済ませる

ブラウザを開いて完了する認証 (CLI のログイン、OAuth の同意) は、SSH 越しや人のいない夜には終わらないことがある。実際に、SSH 越しの CLI のログインが「Completing authentication」のまま進まなかった。

- 昼のうちに人間が済ませる。済まない場合は、CLI を使わない方法を探す。例: 認証のプロバイダーの公開の鍵 (Publishable Key) と、トークンの公開の検証鍵 (JWKS) で検証すれば、サーバーに秘密の鍵を置かずに済み、CLI のログインも要らない。
- 夜に認証が切れていたら、その提供元への操作は止め、それを要しない作業を進める。

## 戻る点を仕組みで作る

- デプロイの手順 (スクリプトや make の目標) は、作業ツリーに未コミットの変更があれば、デプロイを拒む。戻る点 (コミット) を、エージェントの心がけでなく仕組みで作る。無人のエージェントは、言われるまで git を使わないことがある (geo-software-swarm の unattended-runs)。
- 出した版の ID と、そのコミットを対で記録する。前の版に戻すとき (geo-software-deploy の verify の「戻す」) に使う。

## 秘密の扱い

- 値は人間が設定する。エージェントは名前だけを知り、値を表示しない。
- 人間に値を渡す必要があるとき (初回のログイン用のリンクなど) は、人間が自分の端末で表示するコマンドを渡す。
- 合言葉やトークンを DB に保存するときはハッシュにする。
