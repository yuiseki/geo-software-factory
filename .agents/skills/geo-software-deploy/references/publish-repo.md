# リポジトリを公開する

リポジトリを公開すると、今の中身だけでなく全履歴が読まれる。公開の範囲が昼に合意されていることを確かめてから、次の点検をする。

## 全履歴を点検する

- 秘密: 鍵、トークン、秘密鍵、`.env` が、どのコミットにも入っていないこと。
- 手元のパスと手元の生成物: ホームディレクトリのパスや、`__pycache__` のようなキャッシュが入っていないこと。
- 消したはずの記述: 誤記や、公開しないと決めた情報を本文から消していても、古いコミットに残っていることがある。消した文で全履歴を検索する。
- 再配布の条件が分からないデータ: 出典や再配布の条件を確かめていないデータは、形式の見本 (`*.example.json` など) だけを置き、本物は `.gitignore` に入れる。
- 公開しないブランチ: 退避用のブランチなどは押し出さない。公開するブランチだけを指定して押し出す。

## 見つかったら

- 履歴を書き換える前に、リポジトリ全体を退避する (`git bundle create <ファイル> --all`)。
- 置き換え (`git filter-repo --replace-text`) か、ファイルごとの除去 (`--path-glob ... --invert-paths`) で書き換え、全履歴を検索し直して消えたことを確かめる。
- 書き換えで消したものが操作の履歴 (reflog) から辿れないよう、期限切れにして掃除する。
- 履歴の書き換えは取り消せない操作なので、昼に承認を得てから行う。

## 説明文

- リポジトリの説明文は、何であるかと、使うと何が起きるかを 1 文ずつ。言語は README に合わせるか、本人の指定に従う。
- ライセンスのファイルを置き、README にライセンスと出典を書く。
