# 本番の URL で確かめる

デプロイが成功したことは、本番で動くことを意味しない。完成の条件を、本番の URL で確かめ直す。

## 順番

1. API: 主な読み出しの API を `curl` で取り、状態コードと中身の形を確かめる。認証が要る API は、認証なしで拒まれること (401 や 403) も確かめる。
2. 静的ファイル: トップページと、画面の URL (直接開いたときの SPA の振る舞い)、データのファイルを取得する。
3. 非公開のもの: 公開してはいけないデータが、認証なしの読み出しに含まれないことを確かめる。画面で隠しているだけになっていないか。
4. ブラウザ: 本番の URL を開き、完成の条件の画面のシナリオを動かす。コンソールのエラーとネットワークの失敗を記録する。地図は WebGL が要るので、ヘッドレスなら WebGL を有効にする (geo-software-build の testing)。
5. スクリーンショット: 撮って自分の目で見る。README に載せるものは、写したい状態 (全部のパネルに映像が出ている、など) になるまで待つか再読み込みする。
6. 端末をまたぐもの: 本番でも、ブラウザの文脈を 2 つ作って、片方の書き込みがもう片方に届くかを確かめる。

## 古い版を見ていないか

- デプロイの直後は、古い版や 404 が返ることがある。数秒待って確かめ直す。
- Service Worker を使う PWA は、端末に古い画面が残る。画面に版や同期の状態を出しておくと、古い版を開いている端末を見分けられる。データの取得はネットワークを先にし、失敗したときだけキャッシュを使う。

## 報告に書くこと

- 本番の URL と版の ID。
- 確かめたことと結果 (完成の条件ごと)。確かめられなかったことは、確かめられなかったと書く。
- スクリーンショットの置き場所。
