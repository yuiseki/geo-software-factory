# ブレーキを外す順番

ダークファクトリーは、一度に到達する状態ではない。人間の確認 (ブレーキ) を 1 つずつ外していった先にある。外すかどうかは、人間の感覚ではなく、評価の証拠で決める。外したブレーキは、証拠が崩れたら戻す。

考え方は、shokai/agent-skills の software-factory-mode (MIT) の、基本の手順に「外したブレーキ」だけを重ねる構成を参考にした。ここでは、外す根拠を評価の数字に結び付けた。

## ブレーキの持ち方

- 基本の手順は、ブレーキをすべて掛けた状態で書く。外したブレーキは、別の短い一覧 (プロダクト概要の「準備したもの」、または群れの設定) に 1 行ずつ書く。戻すときは、その行を消すだけで済むようにする。
- 一覧の各行に、外した日、根拠にした証拠、戻す条件、決めた人を書く。
- ブレーキを外すことは、エージェントへの指示を変えることなので、人間が昼に承認する (統治の層)。エージェントは、外す候補と証拠を朝の報告に出すところまでを行う。
- 朝の報告には、その夜にどのブレーキを外した状態で動いたかを書く。

## 外す順番の例

危険の小さいものから外す。上の段を外して証拠が積み上がってから、次の段に進む。

| 段 | ブレーキ (人間がすること) | 外す根拠にする証拠 | 戻す条件 |
|---|---|---|---|
| 1 | 夜に入る前に、作る計画を人間が承認する | 判断の方針だけで決めた夜の判断のうち、朝に人間が覆したものが少ない | 覆された判断が続く |
| 2 | プレビューから本番への切り替えを人間が行う | 本番で評価したシナリオの合否が、プレビューでの合否と食い違わない。切り戻しを実際に試した | 本番だけで落ちるシナリオが出る |
| 3 | 利用者に届く PR のマージを人間が承認する | 壊した版を評価が落とせている ([eval-of-eval](eval-of-eval.md))。逃げた不具合の率が昼に決めた値を下回る ([progress](progress.md)) | 逃げた不具合の率が値を超える。評価の評価で見逃しが出る |
| 4 | 群れの予定の頻度や役割の配分を人間が変える | 費用と使用量が予算の内側に収まり続けている | 予算を超える |

## 外さないブレーキ

次は、どれだけ証拠が積み上がっても外さない。ダークファクトリーでも人間が設計し、責任を持つところである。

- 評価のシナリオ、評価の閾値、CI の設定、エージェントへの指示を変えるときの人間の承認。
- 昼に与えた範囲を超える、取り消せない操作 (削除、公開範囲の拡大、課金の増加)。
- 停止スイッチ。

## 証拠の読み方

- 何も起きなかったことは、証拠にしない。確かめた範囲 (シナリオの数、端末、期間) が狭ければ、逃げた不具合が 0 件でも外さない。
- 外したあと、戻す条件を満たしたら、エージェントは自分でブレーキを戻してよい (掛ける側への変更は安全側なので承認を待たない)。戻したことと理由を朝の報告に書く。
