# 地図のアプリで外から観測できるもの

シナリオの「観測」と「合格の判定」に使えるもの。ブラウザの自動操作 (Playwright など) を前提にする。上ほど機械で判定しやすい。

## 配るデータが地理として正しいか

見た目が正しくても、座標が投影座標 (メートル) のまま、緯度と経度が逆、リングが閉じていない、地物の半分が対象の範囲の外、ということがある。地図に載せる GeoJSON は、描画の前に、プログラムで判定する。LLM にも目視にも任せない。

- [scripts/geocheck.py](../scripts/geocheck.py) を使う。標準ライブラリだけで動く。`python3 geocheck.py data.geojson --expect-bbox 122,20,154,46 --require-props name,source --min-features 100` のように、対象の範囲、必ず要る属性 (出典を含む)、件数の下限を、昼に決めた値で渡す。
- 判定するもの: GeoJSON の形、座標が度の範囲か (外なら投影座標を疑う)、緯度と経度の取り違え、対象の範囲の外の点、(0, 0) の点、古い `crs` の項目、リングの閉じと点の数、自己交差、外側のリングの向き、必ず要る属性、空の集まり。
- 終了コードが 0 でなければ不合格。警告 (向き、(0, 0)、`crs`) は報告に載せ、昼に決めた方針で扱う。

## 描画されたか

- 地図の初期化: ライブラリの読み込み完了の印 (MapLibre GL JS なら `load` と `idle` のイベント、`map.loaded()`、`map.areTilesLoaded()`)。ページから評価用に地図のオブジェクトを参照できるようにしておくと判定しやすいが、利用者の経路を変えない範囲にする。
- 実際に何かが描かれたか: スクリーンショットの地図の領域の色の分散や明るさ。真っ白、真っ黒、単色は描画の失敗を疑う。WebGL の canvas は、既定では描画のあとに中身を読み出せないことがあるので、ピクセルはスクリーンショットから測る。
- WebGL が使えるか: ヘッドレスのブラウザでは WebGL2 が無いことがある。評価の環境で WebGL を有効にしたうえで、使えないときの表示 (文言が本当の原因を言っているか) も別のシナリオで確かめる。

## 何が描かれたか

- 地物の数と中身: 表示中の地物を問い合わせる (MapLibre GL JS なら `queryRenderedFeatures`、Leaflet ならマーカーの DOM の数)。期待する件数、属性、状態 (解除済みの色など) と比べる。
- 表示範囲: 中心、ズーム、範囲 (`getBounds`) が、期待する地物を含んでいるか。初めの表示範囲が場面に合っているか (振り返るときに現在地まで広がっていないか)。
- 一覧と地図の一致: 一覧の件数と地図の地物の数、絞り込みを掛けたときの両方の変化。

## 通信

- タイル、スタイル、データの要求の成否と件数 (ネットワークのログ)。4xx、5xx、CORS の失敗が無いか。
- 想定外の送り先が無いか (公開してはいけないデータを送っていないか、規約で禁じられた取得をしていないか)。
- 非公開のデータが、認証の無い読み出しの応答に含まれないか (画面で隠しているだけになっていないか)。

## 帰属表示と出典

- 地図データとタイルの帰属表示が、画面に見える状態で出ているか (DOM の文言と、表示されていること)。小さい画面で折りたたまれる場合、開けば読めるか。
- 写真やデータの出典が、対応する表示の近くに出ているか。

## 現在地と端末

- 現在地: ブラウザの位置の偽装 (Playwright なら文脈の `geolocation` と、位置の許可) で、旅先にいる状態を作る。許可しないときの振る舞いも確かめる。
- 端末: 画面の大きさ、端末の画素密度、タッチの有無、モバイルとしての扱いを切り替える。ピンチやスクロールの奪い合い (二本指で地図を動かす設定) も確かめる。
- ブラウザ: Chromium、Firefox、WebKit で同じシナリオを動かす。ライブラリの「環境の違いと保守」(geo-software-library) で CI が確かめていないブラウザは、ここで確かめる価値が高い。

## 保存と同期

- 書き込んだものが、再読み込み、別の端末 (別のブラウザの文脈)、オフラインからの復帰のあとに残っているか。
- 同期の状態の表示 (送信待ち、最後の成功、失敗) が、実際の状態と一致しているか。

## 見た目

- スクリーンショットを撮り、参考の画面と並べる。崩れ (重なり、はみ出し、折り返しで潰れたボタン)、文字の読みやすさ、色の意味 (解除済みが緑) は LLM の判定に回す ([judging](judging.md))。
- 時間で変わる画面 (動画、ライブカメラ、アニメーション) は、領域ごとの明るさを測って、条件を満たすまで待つか再読み込みする。
