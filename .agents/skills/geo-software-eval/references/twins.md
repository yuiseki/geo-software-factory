# 外部のサービスの代役

地図のアプリは、タイル、スタイル、ジオコーダ、認証、写真の置き場所など、外部のサービスに頼る。評価のたびに本物を呼ぶと、利用料、レートリミット、利用規約、不安定さ、危険な操作の問題が出る。外部のサービスの振る舞いを再現した代役 (StrongDM の Digital Twin Universe の考え方) で評価し、本物でしか分からないことは本番の確認に回す。

## 代役の例

| 外部のサービス | 代役 | 本物でしか分からないこと |
|---|---|---|
| 地図のタイルとスタイル | 範囲を絞ったタイルを手元で配る (PMTiles を静的に置く、自前のタイルサーバー)。決まった範囲だけを返す | 提供元の障害、キーの制限、課金単位、スタイルの更新 |
| ジオコーダ、POI 検索 | 決まった入力に決まった結果を返す代役。表記ゆれや見つからない場合も返す | 本物の網羅率、レートリミット |
| 認証のプロバイダー | 代役の SDK をブラウザの通信の差し替えで配り、わざと遅らせて読み込ませる。トークンは手元の DB の合言葉など | 本物のログインの画面、許可するオリジンの設定、トークンの更新 |
| 位置情報 | ブラウザの位置の偽装 | 端末の GPS の誤差、許可のダイアログの振る舞い |
| 写真や画像の置き場所 | 手元に保存した写しを返す | 公開設定、削除、URL の失効 |

地図のタイル、スタイル、ジオコーダのような HTTP の代役は、[scripts/twin.py](../scripts/twin.py) で立てられる。手元のファイル (Range に応じるので PMTiles も) と、「パスと問い合わせ」ごとの決まった答えを配り、下の失敗を回数で決めて起こし、来た要求を 1 行ずつ記録する。

## 代役を作るときの注意

- 代役は、正常な応答だけでなく、失敗 (タイムアウト、5xx、空の応答、壊れたデータ、遅い応答) も返せるようにする。エッジケースのシナリオはここで作る。
- 代役の振る舞いは、本物の文書や、本物から一度取った応答に合わせる。推測で作った代役で合格しても、本物で動く保証にならない。
- 公開の OpenStreetMap のタイルサーバーや Nominatim のように、利用の方針で大量の取得や評価目的の取得を禁じているものは、評価で叩かない。代役か、許された自前の写しを使う。

## 代役での合格と本物での合格を分ける

- 評価の報告で、どのシナリオを代役で、どれを本物で確かめたかを分けて書く。
- 代役で合格したシナリオのうち、外部のサービスに強く頼るものは、デプロイ後に本物 (本番の URL) で少なくとも 1 回動かす。
