# 受託・業務・自治体向け案件の追加質問

業務地図システム、受託開発、自治体・行政向け案件では、個人向けや自社 SaaS と違い、作るものだけでなく「検収条件」「既存システム連携」「納品先の環境」「引き継ぎ」が昼のうちに決まっていないと、夜に手戻りや納品不能が起きる。以下の観点を、選択肢で 1 問ずつ確かめ、`product-brief.md` の「完成の条件」「準備したもの」「判断の方針」に落とす。

## 1. 契約の形と検収条件

| 聞くこと | 選択肢の例 | 何が決まるか |
|---|---|---|
| 検収の基準 | A 受け入れテスト項目書の全件合格 / B 発注者担当者の操作確認 / C 本番環境での稼働確認 | `geo-software-eval` のシナリオをそのまま検収証跡に使えるか |
| 納入物の範囲 | A 動くアプリのみ / B ソースコード + 設計書・運用手順書 / C コンテナ・データ生成スクリプト一式 | 朝の報告と引き渡し文書に何を含めるか |
| 納品先のリポジトリ | A 開発側で管理 / B 発注者の GitHub/GitLab へ納品 / C オフラインの成果物一式 (zip/tar) | `geo-software-deploy` の手順と権限の範囲 |

## 2. 既存台帳・基幹システム連携と認証

| 聞くこと | 選択肢の例 | 何が決まるか |
|---|---|---|
| 既存システムとの連携 | A 連携なし (ファイル取り込みのみ) / B 既存 DB・API から参照 / C 既存システムへ書き戻し | `geo-software-arch` の正本と `geo-software-protocol` |
| 認証と組織境界 | A 社内・庁内 IdP (Entra ID / SAML / OIDC) / B 部署・自治体ごとの行単位アクセス制御 / C 公開のみ | `geo-software-auth` のプロバイダーと RLS の有無 |
| 端末とブラウザ制約 | A モダンブラウザのみ / B 庁内指定端末・特定ブラウザ版 / C 現地調査用タブレット (オフラインあり) | `geo-software-library` と `geo-software-ux-design` |

## 3. ネットワーク境界・非機能要件・引き継ぎ

| 聞くこと | 選択肢の例 | 何が決まるか |
|---|---|---|
| 稼働ネットワーク | A 通常のインターネット / B 閉域網 (LGWAN / VPN / プロキシ配下) / C 完全エアギャップ (外部通信ゼロ) | ベースマップの自前配信、`airgap-onprem.md` の適用要否 |
| 障害許容と復旧目標 | A ベストエフォート / B 営業時間内復旧 (RPO 24h / RTO 4h など) / C 24/365・冗長構成 | `geo-software-ops` の `handover-sla.md` と予算 |
| 納品後の保守体制 | A 開発側が継続保守 / B 発注者または別ベンダへ引き継ぎ / C 売り切り | 手順書・台帳・監視アラートの引き渡し先 |
| アクセシビリティ要件 | A 一般的な配慮のみ / B JIS X 8341-3 達成等級 AA 準拠 | `geo-software-ux-design` のキーボード・代替テキスト・コントラスト要件 |

## よくある見落とし

- 庁内プロキシ配下や LGWAN 接続系では、外部の CDN (フォント、アイコン、地図タイル、解析スクリプト) が一切読めないことがある。`判断の方針` に「外部 CDN 禁止・全アセット同梱」を明記する。
- 自治体の公共案件では、GIS データのライセンスだけでなく「測量法による承認申請が発注者名義か受注者名義か」「帰属表示の文言を画面と印刷物の両方に出すか」を昼に確認する。
