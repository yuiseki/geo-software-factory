# 入口の洗い出し

攻め手が最初に触れるのは、認証なしで使える入口と、誰でもすぐ作れる一般の利用者で使える入口である。監査はここから始める。画面に出ている操作ではなく、サーバーが受け付けるもの全部を数える。

## 洗い出し方

- ルートの定義 (Workers の `fetch` の分岐、フレームワークのルート、API の定義) を読み、受け付けるパスとメソッドを全部書き出す。画面から呼ばれていないものも数える。
- デプロイの設定 (wrangler の設定、ホスティングの設定) から、公開される名前 (独自ドメイン、workers.dev、プレビューの URL、静的ファイルの置き場) を書き出す。
- 静的ファイルの配信先 (R2、ストレージのバケット、CDN) が、一覧や任意のキーの読み出しを許していないかを確かめる。
- 入口ごとに、認証の要否、一般の利用者で呼べるか、画面を通さずに直接呼べるか (CAPTCHA や入力の検査が画面にだけあって、API に無いか) を表にする。

## 地図のプロダクトに特有の入口

| 入口 | 見落としやすい点 |
|---|---|
| タイルの配信 (`/tiles/{z}/{x}/{y}`、PMTiles の Range 要求) | 認証の無いことが多い。非公開の地物や属性がタイルに入っていないか。極端なズームと範囲 |
| 地物の検索 (`bbox`、`near`、`limit`) | 範囲と件数の上限。全世界の範囲、負の値、逆転した範囲、ズーム 0 での全件 |
| ジオコーディングとルート検索の中継 | 自分の鍵で上流を呼ぶので、他人が無料の中継として使える |
| タイルや画像の中継 (プロキシ) | 任意の URL を取りに行けると、内部のネットワークやクラウドの metadata への到達口 (SSRF) になる |
| スタイルの JSON | 利用者が指定できると、任意のタイルの URL や画像を読み込ませられる |
| 地物の投稿、写真の投稿、ファイルの取り込み (GeoJSON、KML、GPX、Shapefile の ZIP、CSV) | 大きさ、頂点の数、XML、ZIP の中のパス、写真の位置情報 |
| 共有のリンク、埋め込みの地図 | 推測できる ID、期限の無いリンク、埋め込み先からの鍵の流用 |
| 現在地や移動の記録の受け取り | 他人の位置を書き込めないか、精度をどこまで保存するか |
| WebSocket やリアルタイムの配信 | 購読の範囲の認可、接続の数の上限 |

## 表の形

| 入口 | 認証 | 一般の利用者で呼べるか | 画面を通さずに呼べるか | 調べた領域 |
|---|---|---|---|---|
| `GET /api/places?bbox=` | なし | はい | はい | 認可、濫用 |
