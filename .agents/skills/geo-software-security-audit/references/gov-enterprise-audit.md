# 自治体・エンタープライズ向けセキュリティ監査観点

一般公開の地図アプリ向けの 5 領域 (認証・認可・注入・濫用・露出) に加え、自治体や業務システムでは「ネットワーク分離境界」「操作の証跡」「調達基準」に特有の監査項目を確認する。

## 1. 自治体の三層分離とデータ無害化境界

総務省の自治体情報セキュリティ対策では、ネットワークが原則 3 層に分かれる。システムがどの層に置かれ、どの層とファイルをやり取りするかを確認する。

| 層 | 典型的な地図システムの用途 | 監査で確認すること |
|---|---|---|
| **マイナンバー利用事務系** | 住民基本台帳・税・福祉台帳に紐づく地図 | 外部通信の完全遮断、端末へのキャッシュ・印刷・CSV 持ち出し制御 |
| **LGWAN 接続系** | 庁内業務 GIS (道路・上下水道・都市計画・防災) | インターネット系からのファイル取り込み時に無害化処理 (SVG/HTML 内のスクリプト除去、GeoJSON/CSV の再シリアライズ検証) を通っているか |
| **インターネット接続系** | 住民向け公開ハザードマップ・観光・施設案内 | 庁内正本 DB へ直接接続せず、公開用スナップショット/タイルのみを片方向同期しているか |

- **SVG / KML / GeoJSON アップロードの無害化**: 職員や市民がアップロードした KML / SVG / GeoJSON をそのまま描画・再配布すると Stored XSS になる。アップロード時はパーサでジオメトリと許可された属性キーだけを抽出し、JSON として再生成する。

## 2. 操作監査ログ (Audit Trail)

業務・自治体 GIS では「誰が・いつ・どの個人情報/重要施設データを閲覧・検索・印刷・CSV 出力・編集したか」を追跡できることが求められる。

- **記録すべき最小項目**: `timestamp (UTC)`, `actor_id` (ユーザー ID), `tenant_or_dept` (組織/自治体 ID), `action` (`view`, `search`, `export_csv`, `print_pdf`, `create`, `update`, `delete`), `resource_type`, `target_ids` (または検索条件・bbox), `source_ip`, `result` (`allow` / `deny`)。
- **改ざん防止と秘密除外**: 監査ログはアプリユーザーから変更・削除できない追記専用ストレージまたは別 DB ロールへ書き出し、アクセストークンや個人番号などの機微値そのものはログに書かない。
- **位置・機微情報の過剰出力防止**: API の一覧応答や CSV 出力が、画面に表示していない裏の個人情報カラム (住民氏名、電話番号、要配慮者フラグなど) を含んでいないかレスポンス JSON を直接検査する。

## 3. 調達基準・外部サービス要件 (ISMAP / 閉域接続)

- **ISMAP / クラウド基盤**: 政府・自治体向けクラウド環境を使う場合、採用した認証・ホスティング・DB サービスが ISMAP 登録済みか、または調達仕様書で許容された構成かを `geo-software-auth` / `geo-software-arch` の選定記録と照合する。
- **通信経路の保護**: 閉域網内であっても HTTP 平文を避け、内部 CA 証明書による TLS、HSTS、および CORS の厳格なオリジン限定 (`*` 禁止) が掛かっているかを確認する。
