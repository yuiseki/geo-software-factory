# geo-software-swarm

初版を一晩で作って出すところまでは、geo-software-build と geo-software-deploy で行う。だが、試作から製品までの間には、不具合、エッジケース、退行、互換性の崩れ、不安定な CI、リリースといった長い尾がある。このスキルは、その長い尾を、定期的に起きるエージェントの群れで処理し続ける仕組みを立ち上げて動かす。設計は Jiang と Lysenko の Instant Software Factories (arXiv:2610.36254、2026、CC BY 4.0) の考え方に従い、地図のプロダクトに合わせた。

| reference | 読むとき | 中身 |
|---|---|---|
| [roles](references/roles.md) | 群れの役割を決めるとき | 見つける、直す、関門、舵取りの役割と、地図のプロダクトで足す役割 |
| [board](references/board.md) | 掲示板の使い方を決めるとき | issue、PR、チェック、ラベル、メモの書き方。各回は起きて、読んで、1 つだけして、終わる |
| [governance](references/governance.md) | 群れを動かす前に、必ず | 停止スイッチ、取得した内容の指示の無視、権限の検証、マージの関門、評価と指示の変更の統治 |
| [bootstrap](references/bootstrap.md) | 群れを立ち上げるとき | 1 回の設定の会話: 調べる、人間に 1 度だけ聞く、設定の PR、統治を試す、承認、予定を有効にする |
| geo-software-eval の [progress](../geo-software-eval/references/progress.md) | 進み具合を測るとき、朝の報告を書くとき | マージ数でなく、独立に価値づけされ、検証され、届いた変更で測る。逃げた不具合の数え方 |

## 前提

- テストと CI のあるリポジトリと、公開済みの初版 (geo-software-build、geo-software-deploy)。
- 実装から切り離した評価のシナリオ (geo-software-eval)。群れの評価者が使う。
- 掲示板 (GitHub など) への書き込みの権限と、定期実行の仕組み (Claude Code のスケジュールされたタスク、cron など)。
- 対象は、1 つの PR に収まり、1 時間待てる仕事。本番の大きな移行や、複数のリポジトリにまたがる仕事は対象外にし、人間の昼の判断に回す。

## 進め方

1. [bootstrap](references/bootstrap.md) に従って、1 回の設定の会話で立ち上げる。人間に聞くのは 1 度だけ、まとめて聞く (予算、優先する品質、承認者、止める条件)。
2. [roles](references/roles.md) から役割を選び、それぞれに「常に追う目的」と予定 (1 時間に 1 回以下から) を決める。
3. [governance](references/governance.md) の統治の層を設定し、予定を有効にする前に、各制限が本当に効くことを試して確かめる。道具の一覧を絞っただけでは、権限は強制されないことがある。
4. 設定を PR にし、人間の承認を得てから予定を有効にする。
5. 動かしている間は、舵取りの役割が掲示板を読み、進み具合 (geo-software-eval の progress) と費用と使用量の上限を見て、予定の頻度、モデル、役割の配分を予算の範囲で調整する。
6. 朝の報告には、マージ数ではなく、届いた変更、逃げた不具合、評価や指示への変更、止めたことを書く。

## 原則

- 中央の指揮者を置かない。役割どうしは、掲示板に残した痕跡 (issue、PR、チェック、コメント) を読んで動く。
- 各回は記憶を持たない。続きに要ることは掲示板に書く。古いメモは誤らせるので、日付を付け、古いものを疑う。
- 群れは自分の仕事を増やし、自分の評価を書き換え、判定より先にマージできてしまう。これを前提に、評価は群れが書き換えられない場所に置き、進み具合は時間を置いて測る。
- 統治の層は、協調の仕組みと分けて置くが、省かない。危険の大きさに合わせて強さを変える。
- 夜の原則 (AGENTS.md) はそのまま当てはまる: 拒まれても朝を待たずに承認の要らない方法で残す、使用量の上限を 5 時間おきに確かめる、事実を推測で埋めない。

## 出力

- 設定の PR: 役割、予定、統治の設定、統治を試した記録。
- 定期の報告: 進み具合 (届いた変更、逃げた不具合、目的ごとの状態)、費用、評価と指示への変更の一覧、止めたこと。
