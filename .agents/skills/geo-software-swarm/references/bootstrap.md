# 立ち上げ

1 回の設定の会話で群れを立ち上げる。人間に聞くのは 1 度だけにまとめる。AGENTS.md の「昼」の仕事を、群れのために行うものである。

## 手順

1. 調べる: リポジトリ、CI、テスト、評価のシナリオの置き場所、掲示板と定期実行の権限、公開の手順を読む。人間に聞かずに分かることは聞かない。
2. 人間に 1 度だけ聞く: 次をまとめて、選択肢で答えられる形で聞く。
   - 予算: 1 週間の LLM の費用、CI の費用、人間のレビューの時間の上限。
   - 優先する品質: どの目的を一番守るか (地図が出ること、データの鮮度、速さ、帰属表示、端末の広さ)。issue の重さの基準。
   - 承認者: 誰が、どの種類の変更を承認するか。
   - 止める条件: どんなときに群れを止めるか (費用の超過、逃げた不具合の率、使用量の上限)。
   - 公開の方針: 修正をどの頻度で、どの範囲に出すか。公開の前に置く確かめの時間。
   - 使用量の上限をまたいで自分を起こしてよいか (AGENTS.md の昼の準備)。
3. 設定を作る: 役割 ([roles](roles.md))、予定、ラベル、停止スイッチ、マージの関門を設定し、設定の PR を出す。
4. 統治を試す: 停止スイッチで書き込みが止まること、各役割が許された操作しかできないこと、関門が通らない PR を止めることを、実際に試す ([governance](governance.md))。結果を設定の PR に書く。
5. 承認を得る: 人間が設定の PR を承認する。
6. 予定を有効にする: 頻度は低く (1 時間に 1 回以下) 始め、舵取りの役割が進み具合と費用を見て調整する。

## 立ち上げの評価

立ち上げがうまくいったかは、次で見る。

- 立ち上げにかかった人間の時間と、聞いた回数。
- 統治を試したときに見つかった、効いていなかった制限の数。
- 最初の、独立に検証されて利用者に届いた変更までの時間 (geo-software-eval の progress)。
