# CI の点検表

公開の前に、組んだ CI をこの表で点検し、結果を朝の報告に入れる。「いいえ」には理由を書く。

## 試験

- [ ] 地図に載せるデータを、geocheck か同じ役割の試験で判定している
- [ ] 期待値を自分のコードでなく、版を固定した別の道具で作っている (面積、距離、座標の変換がある場合)
- [ ] サーバーの試験を、本番と同じ実行環境と本物の DB で流している
- [ ] 画面の配線 (時間切れ、トークン待ち、実行中の再要求) の試験がある
- [ ] 本物のブラウザで、地図が描けた (真っ白でない) ことを画素で確かめている
- [ ] 描画の比較がある場合、許容を明示し、フォントと画面の大きさを固定し、差分の画像を残している
- [ ] 監査や評価で見つかった不具合の、回帰の試験がある (直す前に落ちることを確かめた)

## 通信とデータ

- [ ] 試験は手元で閉じ、公開のタイル、フォント、外部の API を呼ばない
- [ ] 手元以外への通信で、試験が落ちる (わざと外へ通信する試験で確かめた)
- [ ] 公開の OSM のサーバーを呼んでいない
- [ ] 試験のデータの出どころとライセンスを書いた。大きなデータは版を固定した URL と sha256 で取る

## CI

- [ ] 合否は 1 つの段にまとまり、それがマージの条件になっている
- [ ] 整形、lint、型検査で、警告を誤りとして扱っている
- [ ] GPU の無い CI で、ソフトウェアの描画 (SwiftShader、lavapipe、llvmpipe) を使っている。本物の GPU でしか言えない試験は、理由を書いて外した
- [ ] 依存のライセンスと、秘密の漏れを検査している
- [ ] 配布物の大きさの上限がある (Web の場合)
- [ ] 落ちたときに、画像、コンソール、通信の記録が CI の成果物に残る
- [ ] 毎晩の段 (全部のブラウザ、依存の最新版) が、落ちたら issue を立てる

## 不安定な試験

- [ ] 再試行は 1 回までで、再試行のときに記録を増やしている
- [ ] 隔離した試験に、理由、担当、期限がある
- [ ] 落ちると分かっている一覧は、通るようになったら落ちる

## 仕組みそのもの

- [ ] わざと壊した版で、試験が落ちることを確かめた
- [ ] 描画の比較の仕組みが、期待の画像どうしで一致と判定することを確かめた
