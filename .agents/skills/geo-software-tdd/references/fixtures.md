# 試験のデータと通信

試験は手元で閉じる。公開のタイル、フォント、スプライト、外部の API に試験で通信すると、相手に負荷を掛け、相手の変化で試験が揺れ、ネットワークの無い CI で落ちる。どのライブラリも、手元で閉じることを既定にしている (根拠は [sources](sources.md))。

## 地図のデータを手元に置く

- 小さなタイルの一式を置く: 試験に使う範囲の 1〜2 枚のベクトルタイル (MVT か PMTiles)、スプライト、使う範囲のグリフ。手元のサーバーから配る。
- スタイルの URL を、1 つの関数で手元に書き換える。試験のスタイルには、手元を指す印 (例: `local://`) を書き、試験の前に手元のサーバーの URL に置き換える (MapLibre)。
- タイルの読み込みが要らない試験 (Leaflet のラスタの層など) は、作った URL が正しいかだけを確かめ、読み込みが要るときは data URI の小さな画像を使う (Leaflet)。
- WMS や ArcGIS のエンドポイントは、決まった画像を返す偽のエンドポイントにする (OpenLayers)。
- 描画のエンジンが手元の保存先 (SQLite のキャッシュなど) を持つなら、試験のデータをそこに入れておき、ネットワークを使うのは明示の印を付けたときだけにする (MapLibre Native)。

## 外への通信で落とす

- 試験の中で、手元以外への要求があったら落とす。ブラウザの試験なら通信の差し替えで、手元以外の宛先を止めて記録する。
- 外へ通信しないと証明する段を、CI に 1 つ置く。ソケットを使えなくした環境で試験を回し、通信の印を付け忘れた試験を見つける (cartopy は `--disable-socket` の段を持つ)。
- 存在しない宛先 (`.invalid` で終わる名前) と、差し込める取得の部品で、外部の宛先を表す (maplibre-native-rs)。手元のサーバーは、来た要求を記録し、試験が何を要求したかまで確かめる (RustGIS)。
- 公開の OSM のサーバー (tile.openstreetmap.org、nominatim.openstreetmap.org、overpass-api.de) は、試験でも呼ばない。

## 大きな試験のデータ

- 大きなデータは、リポジトリに入れず、版を固定した URL から取り、sha256 で確かめる。「最新」を取らない (forge3d、mln-rs のベンチマークの準備)。
- 取ったデータは CI でキャッシュする。

## 試験のデータの出どころ

- 試験のデータごとに、出どころとライセンスを書く (ezu は試験のデータの出どころの一覧を置く。RustGIS は QGIS で作った試験のデータの説明を置く)。地図のデータの帰属表示の条件 (ODbL など) は、試験のデータにもかかる。
- 本物のデータを小さく切ったものを使うときは、切り方 (範囲、件数、日付) を書く。作り直せるように、切るスクリプトを置く。

## 外部のサービスの代役

- 認証、決済、メール、地図の API の外部のサービスは、代役で試す。代役は、本物と同じ順序と遅れ (読み込みの遅れ、時間切れ) を再現する (geo-software-build の testing、geo-software-eval の twins)。
- 代役は本物と食い違うことがある。本物でしか確かめられないことは、公開のあとの確かめ (smoke) と、評価者の本番での評価に回す。
