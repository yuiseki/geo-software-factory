# 試験の種類

地図のプロダクトで書く試験を、下ほど重く、遅く、少なくなる順に並べる。各項の括弧は、そうしている例 (根拠は [sources](sources.md))。

## 1. 純粋な処理の単体の試験

スタイルの組み立て、データの変換、URL の作成、座標の計算、範囲の計算。地図を描かずに試せるものは、ここで試す。ブラウザを要する試験と分けて置く (OpenLayers は Node の試験とブラウザの試験を分ける。CesiumJS は WebGL を要る試験を別に分ける)。

- 公開の API で試す。内部の関数を直に呼ぶ試験は、作り替えで壊れやすい。
- 協力する部品を差し替え、試す部品そのものは差し替えない。

## 2. 地図に載せるデータの試験

データを作る処理 (取得、変換、結合) の出力を試す。地図の見た目では、緯度と経度の取り違えや投影座標の混入に気づきにくい。

- 形と範囲: geo-software-eval の [geocheck](../../geo-software-eval/scripts/geocheck.py) で、GeoJSON の形、度の範囲、取り違え、範囲の外、必ず要る属性 (出典を含む) を判定する。
- 期待値は、別の道具で作る: 面積、距離、交差、座標の変換の期待値を、自分のコードでなく、版を固定した別の道具 (shapely と GEOS、pyproj、GeographicLib、QGIS) で作る。期待値を作るスクリプトもリポジトリに置き、作り直して違ったら CI を落とす (RustGIS、GeoPandas)。
- 許容は物理の単位で書く: m、m²、面積の比。浮動小数の生の誤差で書かない。試験の座標は、どの平面でも誤差の出にくい値を選ぶ (RustGIS)。
- 決定性: 同じ入力と乱数の種から、同じ出力 (バイトか hash が一致) が出ること。並列で動かしても、1 本で動かしたときと一致すること (forge3d、RustGIS、ezu)。
- 書き出しの往復: 書き出して読み直し、同じになること。版の違う書き手のファイル (GeoParquet の版、GDAL の版) を試験のデータに置く (GeoPandas)。
- 捨てたものを言う: 変換で落とした地物や属性を、黙って捨てず報告すること。捨てる入力と捨てない入力の両方で試す (RustGIS)。

## 3. サーバーの試験

本番と同じ実行環境で、本物の DB に対して流す (geo-software-build の [testing](../../geo-software-build/references/testing.md))。

- 認証、認可、範囲や件数の上限、巨大な要求の拒否を、geo-software-security-audit の領域ごとに試す。監査で確かめた問題は、ここに回帰の試験として足す。
- でたらめな引数を全部の API に送り、落ちない (500 や panic にならない) こと (RustGIS)。

## 4. 画面の配線の試験

起動時の同期、認証の読み込み待ち、通信の時間切れ、実行中の再要求。配線は依存 (通信、時計、トークン) を差し込める形に切り出して試す (geo-software-build の testing)。

- 通信は、自分の通信の関数をモックせず、通信の層 (偽のサーバーか、ブラウザの通信の差し替え) で差し替える。要求の組み立てまで試せる (MapLibre の AGENTS.md)。

## 5. 本物のブラウザでの地図の試験

地図を作り、読み込み、動かす試験は、本物のブラウザで動かす (Vitest のブラウザのモードと Playwright。Leaflet、OpenLayers、deck.gl)。

- 地図が描けたこと: 描画の領域の画素を読み、真っ白、真っ黒、単色でないこと。WebGL のコンテキストを失って戻したあとも描けること (MapLibre)。
- 待つのは地図のイベント (`load`、`idle`) で、固定の時間で待たない (MapLibre)。
- 時間を止める: アニメーション、`flyTo`、CSS の遷移を、偽の時計で決定的にする (Leaflet)。
- 後始末: 各試験のあと、地図の要素がページに残っていないこと、`remove()` が呼ばれたことを確かめる (OpenLayers は残った `<div>` で試験を落とす)。

## 6. 描画の比較 (基準の画像)

見た目でしか言えないもの (自分のスタイル、主な画面の見え方) だけを、基準の画像と比べる。

- 事例ごとに、スタイル (か画面の状態)、期待の画像、許容を置く。比較は画素の差 (pixelmatch) や、構造の近さ (SSIM)、色の差 (CIEDE2000) を、内容に合わせて選ぶ (MapLibre、MapLibre Native、ezu、forge3d)。
- 許容は明示する (差のある画素の割合など)。環境ごとの違いは、環境ごとの期待の画像で受け止め、選び間違えたら落とす (forge3d は別の描画の土台の基準と照合することを拒む)。
- フォント、表示の大きさ、画素の比を固定する。システムのフォントに頼らない (MapLibre は CI にフォントを入れる。matplotlib は試験の前に設定をそろえる)。
- 落ちたら、実際の画像、期待の画像、差分の画像を CI の成果物に残す (どのライブラリも)。
- 期待の画像を作り直す手段を用意し (MapLibre は環境変数で作り直す)、作り直した画像は人か評価者の目で見てから採用する。
- 先に性質の試験を考える: 子のタイルが親のタイルの 4 分の 1 と一致する (maplibre-native-rs)、隣り合うタイルの境目で絵が食い違わない (ezu)、ある色の画素が N 以上ある。基準の画像より壊れにくい。

## 7. 操作の試験

ドラッグ、ホイール、ダブルクリック、マーカーのドラッグを、本物のブラウザで、画面の大きさを決めて、合成のポインターのイベントで試す (MapLibre、Leaflet)。Vitest のブラウザのモードの既定の枠の大きさでは、座標からの要素の取得がずれることがある (Leaflet の注記)。

## 8. 差分の試験と、性質の試験

- 既存の実装を作り替える、移すときは、同じ入力を両方に与えて結果を比べる。手で選んだ境目の入力と、生成した入力 (proptest、Hypothesis) の両方で (mln-rs の差分の試験)。
- 性質の試験: 往復で元に戻る、範囲の外に出ない、順番を変えても結果が同じ。

## 9. 壊れた入力の試験

- 読み込みの処理 (GeoJSON、KML、Shapefile の ZIP、画像) に、壊れた入力を与えて、落ちずに拒むこと。メモリと時間に上限を掛けて、ファジングを毎晩か、ラベルを付けたときに回す (RustGIS)。
- 展開すると巨大になる入力 (ZIP、画像) に、メモリの上限の試験を書く (RustGIS)。

## 10. 公開のあとの確かめ

- 本番の URL に読み出しだけで当てる (geo-software-deploy の [smoke](../../geo-software-deploy/scripts/smoke.py))。
- 例や画面ごとに、時計を止めてスクリーンショットを撮り、落ちていないかを広く浅く見る (CesiumJS は例のページを全部撮る)。

## 選び方の目安

- 必ず書く: 1、2、3、4、5 (地図が描けたこと)、10。
- 自分のスタイルや見た目が価値の芯なら: 6。
- 操作が価値の芯なら (描く、選ぶ、測る): 7。
- 既存のものを作り替える、移すなら: 8。
- 利用者からファイルを受け取るなら: 9。
