# 詳細パネルと地図の連動 UI

地図上の地物 (POI、施設、区画、車両など) を選んだときに情報をどこへ出すかと、その表示領域に合わせて地図の表示中心をどうずらすかは、地図 UI で最も破綻しやすい箇所である。

## 詳細表示の器の選び方

| 器 | 適している情報量 | 避けるべき罠 |
|---|---|---|
| 地図上ポップアップ (Popup) | タイトル、短い数値、1 つのリンク程度の軽量な情報 | 情報が多いと地図端ではみ出して切れたり、狭い画面で地図を覆い尽くしたりする。画像や長い一覧を Popup に入れない |
| サイドパネル (左ドロワー / 右インスペクタ) | 写真、属性テーブル、編集フォーム、複数アクションなど情報が多い場合 (PC 向け) | モバイル幅でそのまま出すと地図が消える。画面幅が狭いときはボトムシートへ切り替える |
| スナップ式ボトムシート (モバイル向け) | モバイルでの施設詳細、検索結果一覧、ルート案内 | 高さを固定すると「地図も見たい」「詳細も読みたい」の両立ができない。Peek (見出しのみ) / Half (半分) / Full (全画面) の 2〜3 段階で切り替えられるようにする |
| ホバーツールチップ | PC でカーソルを合わせたときの名称・値プレビュー | タッチ端末ではホバーが残り続けるため、ホバー前提の必須情報を置かない。クリック/タップで開く導線を別に用意する |

## 地図の `padding` (視覚的中心) の連動

サイドパネルやボトムシートを開いたまま地物を選択し、`flyTo` / `easeTo` / `fitBounds` で地図を移動するとき、画面全体の幾何学的な中心に地物を移動させると、**地物がパネルやボトムシートの裏に隠れて見えなくなる**。

- 地図ライブラリの `padding` オプション (`{ top, right, bottom, left }`) に、現在開いているオーバーレイ (ヘッダー、検索バー、サイドパネル、ボトムシート) の実際の高さ・幅を渡す。
- 画面サイズが変わったときやボトムシートをスナップ移動したときも、見えている地図領域の中心に対象が収まるように余白を再計算する。
- 地物を選択解除してパネルを閉じたときは、`padding` を元の最小値へ戻す。

## 一覧と地図の同期 UI

検索結果の一覧や属性テーブルと地図を並べる場合は、両者の視線移動と操作が食い違わないようにする。

- **双方向の選択・ホバー同期**: 一覧の項目にホバーまたは選択したとき、地図上の対応するマーカーの色・サイズ・重なり順を即座に強調する。逆に地図上のマーカーを選んだときは、一覧の該当行まで自動スクロールし選択状態を示す。
- **絞り込みと表示範囲の一致**: キーワード検索、タグ、状態フィルタ (例: 営業中のみ) は、一覧と地図の両方に同時に効かせる。片方だけに効くと画面内の情報が矛盾する。
- **地図移動時の再検索**: 地図をパン・ズームした瞬間に自動で一覧を書き換えると、利用者が一覧を読んでいる最中に中身が跳ねてしまう。自動追従が不要な場合は、画面上部または中央下に「この範囲で再検索」ボタンを出し、利用者の操作で更新する。
- **選択中の見失い防止**: 選択した地物がパンによって現在の画面外に出た場合でも、パネル側の情報は勝手に閉じず、パネル内に「地図の中心へ移動」などの復帰操作を残す。
