# 一般的な UI 原則

地図画面であっても、ボタン、パネル、フォーム、文字組み、色の基本的な振る舞いは一般的な Web UI の原則に従う。以下は [ibelick/ui-skills](https://github.com/ibelick/ui-skills) (MIT License, Copyright (c) 2026 Julien Thibeaut, 2026-11-16 確認) の `baseline-ui`、`fixing-accessibility`、`playbook` を基に、地図プロダクトの UI 設計で特に効く項目を整理したものである。

## レイアウトとビューポート

- 全画面の高さ指定に `100vh` (`h-screen`) を使わず、`100dvh` (`h-dvh`) を使う。モバイルブラウザのアドレスバー伸縮で下部の帰属表示やボトムバーが切れるのを防ぐ。
- 固定配置 (`position: fixed` / 画面端のオーバーレイ) には `env(safe-area-inset-*)` を考慮する。
- 重なり順 (`z-index`) はプロジェクト全体で固定のスケール (例: 地図キャンバス 0、地図上のコントロール 10、サイドパネル・ボトムシート 20、ドロップダウン・ツールチップ 30、モーダル 40、トースト 50) を決め、場当たり的な `z-[999]` を作らない。
- 境界は仕切り線 (`border`) の多用ではなく余白と段差 (背景色・影) で分け、情報密度を保ちつつ視線の引っかかりを減らす。
- 入れ子の角丸は外側の半径から内側の余白を引いた同心円状の丸み (`concentric border-radius`) に揃える。

## コンポーネントと操作

- キーボード操作やフォーカス管理を伴う部品 (ダイアログ、メニュー、コンボボックス、タブ、ドロワー) は、自作せずアクセシブルなプリミティブ (Base UI、React Aria、Radix など) を使い、同じ画面内で複数のプリミティブ体系を混ぜない。
- アイコンだけのボタン (ズーム、現在地、閉じる、レイヤー切替など) には必ず `aria-label` を付け、装飾用の SVG には `aria-hidden="true"` を付ける。
- タッチ対象の操作領域は最低 `44px x 44px` 以上を確保し、隣接するボタンどうしには十分な間隔を空ける。
- 削除やデータ破棄などの取り消せない操作には、必ず確認ダイアログ (`AlertDialog`) を挟む。
- 空状態 (検索結果 0 件、登録データなし) には、利用者が次に取れる 1 つの明確なアクション (例: 「条件をリセット」「この範囲を再検索」) を置く。
- エラー表示は画面上部のバナーだけでなく、原因となった入力欄や操作ボタンのすぐ隣に出す。

## タイポグラフィと数値

- 見出しは `text-wrap: balance`、本文は `text-wrap: pretty` を使い、見出しの行間は本文より詰める。
- 緯度経度、距離、面積、件数、時刻などの数値は `font-variant-numeric: tabular-nums` を使い、値が変わっても桁が横揺れしないようにする。
- 狭いパネルやカードの見出しは 1 行に収めて `truncate` または `line-clamp` で省略し、折り返しによって地図領域や隣のボタンが押されないようにする。
- 文字間 (`letter-spacing`) は大きな見出しの微調整以外では不用意に変えない。

## 色とコントラスト

- 1 画面あたりのアクセントカラーは 1 色に絞り、ブランドの強調色をリンクや主操作に温存する。
- グラデーション (特に紫や多色グラデーション) やプライマリボタンへの発光 (グロー) 効果は原則使わない。
- 状態 (選択中、エラー、有効/無効) を色だけで伝えず、アイコンやラベル、境界線を併用する。
- 補助テキスト (注記、更新日時、出典) でも背景との十分なコントラストを確保する。

## 動き (アニメーション) と読み込み

- 移動や開閉のアニメーションはコンポジタプロパティ (`transform`、`opacity`) のみに限定し、`width`、`height`、`top`、`left`、`margin`、`padding` はアニメーションさせない。
- 画面全体や大きな領域に対する `blur()` や `backdrop-filter` のアニメーションは避ける (地図のパン・ズームと重なると描画負荷が跳ね上がる)。
- 操作への反応は `200ms` 以内の `ease-out` を基本とし、閉じる動きは開く動きより短く控えめにする。
- 読み込み中はレイアウトシフト (CLS) を防ぐためアスペクト比や領域を先に確保し、実データの構造に近いスケルトンを表示する。
- `prefers-reduced-motion: reduce` を尊重し、画面外のループアニメーションは停止する。

## UI の言葉とアクセシビリティ

- UI 上のラベルは機能や仕組みの説明文を書かず、具体的な動詞・名詞で短く示す (`stop-describing-ui` の原則)。
- すべての操作要素は Tab キーで到達でき、キーボード利用者にフォーカスリングが見える状態を保つ。
- モーダルやドロワーを開いたときはフォーカスを内部に移し、`Escape` キーで閉じられ、閉じたときに元のトリガーへフォーカスを戻す。
