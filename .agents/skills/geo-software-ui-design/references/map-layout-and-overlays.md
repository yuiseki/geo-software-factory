# 地図の画面構造とオーバーレイ配置

地図ソフトウェアの UI は、縦にスクロールする通常の Web ページと異なり、動的な地図キャンバスの上に操作部品と情報パネルが重なる構造をとる。最初に画面全体の型を決め、四隅の衝突とモバイル特有の破綻を防ぐ。

## 画面レイアウトの 4 つの型

| 型 | 向いている場面 | 構造と注意点 |
|---|---|---|
| 全画面オーバーレイ型 | 探索・ナビ・フィールド調査など地図が主役のアプリ | 地図を `100dvh` で全面に広げ、検索窓・ツールバー・詳細シートを上に浮かせる。オーバーレイが地図面積の 3 割を超えないように保つ |
| 分割 (Split View) 型 | 店舗検索・不動産・属性テーブル連動 GIS など一覧と地図を往復する画面 | PC では左に一覧 (幅 `360px`〜`420px` 程度)・右に地図を並べ、モバイルでは「地図 / 一覧」の切替またはボトムシートへ切り替える |
| 埋め込みカード型 | 記事・施設詳細・ダッシュボードの一部として位置を示す地図 | 小さな地図では操作を制限 (`cooperativeGestures` や静的表示) し、周辺のスクロールを奪わない。帰属表示が面積を圧迫しないか実寸で確かめる |
| 常時表示 (サイネージ・監視) 型 | 操作せずに眺め続ける画面 | ヘッダーや不要な導線を省き、主役の地図や映像と重ならないよう領域を分ける |

## 四隅の衝突回避 (Corner Collision)

地図キャンバスの四隅はコントロールが集中しやすく、画面幅が狭い環境やパネル展開時に重なりが起きやすい。役割ごとに定位置を固定し、同じ角に複数の要素を積まない。

- **右下 (または左下)**: 帰属表示 (Attribution) とスケールバー。帰属表示は利用規約・法令上の必須表示であり、ボトムシートやフローティングボタンの下に隠してはならない。ボトムシートが展開するときは帰属表示をシート上端へ逃がすか、常に最前面かつ操作可能な余白を確保する。
- **左上**: 検索ボックス、現在の絞り込みチップ、または折りたたみ式のサイドパネル起動ボタン。
- **右上**: ズーム (`+`/`-`)、コンパス (回転リセット)、現在地ボタン、レイヤー切替トリガー。スマホでは片手で届くよう右下に寄せる設計もあるが、その場合は帰属表示との重なりを必ず避ける。
- **中央下 (または上)**: 「この範囲で再検索」ボタン、計測中の完了・キャンセルバー、トースト通知。

## モバイル特有のレイアウトの罠

- **アドレスバーによる見切れ**: `100vh` を使うと iOS Safari や Android Chrome で下部 UI と帰属表示がアドレスバーに隠れる。必ず `100dvh` を使い、下端の配置には `env(safe-area-inset-bottom)` を足す。
- **画面端のスワイプバック競合**: 地図の左端や右端からのドラッグがブラウザの「戻る/進む」ジェスチャと競合することがある。サイドドロワーや地図端の操作に頼りすぎず、明示的な閉じるボタンを置く。
- **ソフトキーボード展開時の潰れ**: 検索欄にフォーカスしてキーボードが出た際、地図上のオーバーレイが押し潰されて候補リストが見えなくなることがある。検索結果リストは地図の背後に回さず、検索欄直下または専用オーバーレイとして十分な高さを確保する。
- **最小表示面積の確保**: パネルやツールバーを開いた状態でも、利用者が地図上の現在地や対象物を視認し続けられる最小面積を残す。狭い画面では横並びのサイドバーを無理に出さず、ボトムシートまたは全画面切替にする。
