# unslop-ai-app (AI らしさを抜いた Web UI 規則)

Web アプリの画面を「AI が作った感じ」にせず、日本語の画面とモバイル環境でも破綻しない品質に整えるための規則である。以下は [minorun365/unslop-ai-app](https://github.com/minorun365/unslop-ai-app) (Apache License 2.0, Copyright 2026 Minoru Onda, 2026-11-17 確認。一部項目は Damir Sokolovsky による [unslop](https://github.com/heydamir/unslop) CC BY 4.0 を参考に日本語の画面向けに書き直したもの) の `app-ui-design`、`references/contrast.md`、`agent-app-ui`、`mobile-web-check` を基に、地図プロダクトの UI 設計・実装・検査で適用する項目を整理したものである。

## 1. 情報の引き算

- **作る前に画面の主役を 1 文で書く。** 「この画面で利用者は何を見て、何を押すか」を定め、主役が 2 つ以上になったら画面を分ける。
- **部品を足す前に「これが無いと使えなくなるか」を問う。** 無くても使えるなら置かない。内訳、表示切替トグル、見出し横のバッジ、補助リンクは頼まれるまで置かない。
- **数字の補足を足さない。** 処理時間、経過時間、件数、接続状態の点は、その数字を見た人が何を判断するかを 1 行で言えるものだけ残す。要約の数字カードには見出しと数字だけを置き、内訳や説明文を並べない。
- **設定のチェックボックスや検証用オプションを操作画面に並べない。** 開発・検証用の切り替えは URL パラメータへ逃がし、既定値を本番の値にする。
- **サイドバーは折り畳めるようにする。** PC でも地図や本文を広く使いたい場面がある。
- **引くのは情報で、作りの厚みではない。** 製品らしさを出す面・影・アイコン・状態に応じた色や動きまで削ると「簡素すぎて安っぽい」画面になる。「要らない情報が無いか」と「製品の画面に見えるか」の両方を確かめる。

## 2. AI らしく見える定番の型と直し方

| 型 | 直し方 |
|---|---|
| カードや枠の 1 辺 (左端・上辺) だけに太い色の線を付ける | 面は白か淡い地、角丸、薄い影、細い枠で作る。種類や状態は小さな丸か文字で示す |
| 枠の中に「色付きの地 + 太い左線 + 角丸」の小箱を入れ子で並べる | 文字の太さ、行間、段落の間隔で読ませ、箱の入れ子をやめる |
| 絵文字をアイコン代わりに並べる (🚀 🔥 💡 ✅ ⚠️) | 線のアイコン素材を 1 種類だけ使い、数も絞る。要らなければ何も置かない |
| AI の機能にきらめき (✨) や光る球を付ける | 外す。AI が出した結果そのものを見せる |
| 四角い塗りの番号バッジ (角丸チップに白抜きの数字) | 数字は文字のまま置き、罫線で区切る |
| 見出しの下に小さい文字の注記をもう 1 行足す | 消す。必要な説明は本文の 1 行目へ移す |
| 光る影 (色付き `box-shadow`)、ネオン色の枠、ぼかした色の円を背景に置く | 外す。奥行きは地の明るさの差と細い線で作る |
| 文字へのグラデーションや、紫〜青〜ピンクの派手な背景・ボタンのグラデーション | 地は無彩色にし、強い色は意味のある 1〜2 か所だけ単色で使う |
| 何もかもを丸い錠剤形 (ピル) にする | 部品の大きさに合わせて角丸の半径を変える |
| 「NEW」「PRO」「Beta」のバッジを散らす | 外す。本当に必要な 1 つだけ目立たない文字で示す |
| 確認結果や件数を色付きピルに「太字の数字 + 説明文」で並べる | 同じ画面にある数字のタイルや表と同じ部品にそろえ、外れた項目だけ文字色で目立たせる |
| 同じ大きさのカードを横に並べ、全部に同じ小さなグラフを入れる | 主役のグラフを 1 つ大きく置き、残りは数字だけの小さな表示にする |

## 3. 画面の文言と日本語の組版

### 画面の文言

- **見出しはその場所で何をするかを名詞で示す。** キャッチコピー、対句、比喩、飾りの英字見出し、使っている技術の名前は入れない。消すときは別のキャッチコピーへ言い換えず、機能名へ戻すか要素ごと消す。
- **空の状態を待機メッセージで埋めない。** 「ここに結果が表示されます」「準備中…」は置かず、何も出さないか次に押すものだけを示す。
- **あいさつの見出しや「！」を置かない。** ボタン、見出し、通知のどれも平叙で書く。ボタンや短いラベルの末尾に句点を付けない。
- **ボタンは動作の名前にし、操作を演出する動詞へ言い換えない。** 「送信」「保存」「削除」「アップロード」のように一般的な動詞・名詞を使う。
- **増減には比べる相手を書く。** 「+12%」ではなく「前月比 +12%」のように書く。
- **効能を盛る言葉や作り物に見える見本値を置かない。** 「爆速」「シームレス」「魔法のように」を避け、`12,345` や `XXX` ではなく自然な桁と端数の値を使う。

### 日本語の組版

- **フォントは OS の日本語ゴシックを先頭に並べる。** `-apple-system, BlinkMacSystemFont, "Hiragino Sans", "Noto Sans JP", sans-serif` を基本とする。
- **本文の行間は広めにとる。** `line-height: 1.7〜1.85` を使い、英語向けの既定 (`1.5`) のまま詰まらせない。
- **約物を詰め、太さは 2 段階までにする。** `font-feature-settings: "palt" 1` を見出しと本文に入れ、本文 400 と見出し 600〜700 の 2 段階に絞る (`800` 以上の極太を使わない)。
- **英字大文字 + 広い字間の飾り、小さい文字の負の字間、斜体を使わない。** 日本語書体には本来の斜体が無く機械的に傾くだけになる。
- **数字は桁をそろえる。** `font-variant-numeric: tabular-nums` を付け、桁区切りや小数桁数をそろえる。
- **改行位置を見る。** 見出しやカードの末尾で 2〜3 文字だけが次の行へ落ちたら、文字を縮めず見出しを短くするか残りを本文へ移す。

## 4. 色・コントラスト・余白・アイコン・動き

### 色とコントラスト

- **基調の色相は 1 つ、無彩色と強調の色を 1 つにする。** 強調の色は「面」ではなく「点」で 1 画面数か所までに留め、文字色は「主・副・控えめ」の 3 段階に絞る。枠線は主な文字色を 6〜10% の透明度にした細い線にする。
- **色はすべて CSS 変数に集める。** 文字色と地の色は同じ詳細度の 1 つの規則にまとめて書き、片方だけ上書きされて白地に白文字になる事故を防ぐ。濃い地の上に半透明の下敷きを置くなら暗くする色にする。
- **「メリハリがない」と言われたら主役ではなく周りを落とす。** 罫線や補助ラベルの明るさを下げて差を付ける。候補の色は切り抜きではなく画面全体に当てて並べて比較する。ダークテーマは頼まれたときだけ作り、既定は白基調とする。
- **コントラストは目で判断せず測る。** 本文の文字と地の明度比は `4.5` 以上、大きい太字 (`24px` 前後) は `3.0` 以上、罫線や入力欄の枠は `1.5〜3` を目安にする。ブラウザの開発者ツールで直接テキストを持つ全要素の明度差を一括検査し、低い要素が 0 件になるまで直す。

### 余白と配置

- **余白は `4px` の刻みにそろえる。** `13px` や `7px` のような半端な値を使わない。まとまりの内側は狭く、まとまりの間は広く保ち、縦に並ぶ別ブロック間は `16〜24px` を明示する。
- **入れ子の角丸は `外側の半径 = 内側の半径 + 間の余白` にする** (内側は `4px` 未満にしない)。
- **比べる 2 列は上下の端をそろえる。** 中身の量が変わる場合は両方に同じ高さを与えて中をスクロールさせる。

### アイコンと動き・操作

- **アイコンの絵柄集は 1 つにそろえる。** 既存があればそれ、無ければ `lucide` (大きさ `16px` か `18px`、線幅 `1.5`) を使い、アイコンの色は横の文字と同じ役割の色にする。
- **常に動いている飾りを置かない。** `transition: all`、カードの拡大ホバー、跳ねるスプリング曲線は使わない。曲線は `cubic-bezier(0.22, 1, 0.36, 1)` に統一し、長さはホバー・押下 `120〜180ms`、メニュー `160〜220ms`、登場 `300〜500ms` とする。動かすプロパティは `transform` と `opacity` に限る。
- **メニューはホバーではなくクリック (タップ) で開く。** 外側タップ (`mousedown` と `touchstart`) で閉じる。確認・処理中・結果の 3 段階ダイアログは処理が終わってから閉じる。

## 5. AI エージェント機能やチャット UI を載せる場合

地図アプリに対話検索や AI エージェント画面を載せる場合は、`agent-app-ui` の次の規則を併せて適用する。

- **応答の Markdown は描画して見せる。** `white-space: pre-wrap` のまま記号を並べない。最初のひと言にきらめきの絵文字やロボットの絵を添えず、空画面に例文カードを何枚も並べない。
- **待ち時間と途中経過を状態ごとに描き分ける。** 「考え中」(控えめな光の移動)、「ツール実行中」(1 行の対象名 + 小さな回転印)、「完了」(同じ行を置換し行を増やさない)、「本文生成中」(末尾カーソル、ツール実行中はカーソルを隠す) を分ける。同一状態の重複行を出さず、状態の色は「実行中」と「失敗」の 2 つまでに絞る。
- **人前で操作する画面 (発表・デモ) では見せる画面と操作部品を分ける。** マウスだけで完結させ、ショートカットキー表示や不要な同期状態バッジを見せる画面に出さない。

## 6. モバイル実機相当の確認と出荷前チェック

PC ブラウザの狭い窓は iPhone の代わりにならないため、スマホでも使う地図画面は `mobile-web-check` の手順に沿って確認する。

- **見る順番を固定する。** トップ・子画面・ダイアログ・ログイン画面のすべてで、(1) 上端のステータスバー帯と本文色のつながり、(2) 固定要素と見出し・本文の重なり、(3) 余白の間延び、(4) 下端を引き伸ばしたときの `html` 背景色、(5) 横はみ出し (`document.documentElement.scrollWidth === document.documentElement.clientWidth`) を確かめる。
- **セーフエリアとスクロールの罠を避ける。** `viewport-fit=cover` と `env(safe-area-inset-*)` を使い、背景は画面端まで広げて文字とボタンだけを安全領域へ逃がす。縦のスクロールは `document.scrollingElement` の 1 つだけにし、画面全体を覆う `overflow-y: auto` を作らない。
- **入力欄の `font-size` は `16px` 以上にする。** iOS Safari が `16px` 未満の入力欄フォーカス時に自動拡大して横にはみ出すのを防ぐ。送信ボタンは二重送信 (タッチ終了 + クリック) を検査する。SNS アプリ内ブラウザで後から上の余白が足される場合があるため、固定位置の基準となる見出しは `ResizeObserver` の `border-box` で監視する。
- **出す前の機械検査と最終確認を行う。** `unslop-ai-app` リポジトリの `tools/check-ui.mjs` で AI らしく見える書き方が 0 件になることを確認し、意図して残す行だけ `check-ui-ignore` を付ける。最後に「製品名を別の製品に入れ替えても成り立つテンプレートのままになっていないか」を問い、そのプロダクト固有の主役の見せ方や文言が入っているかを確かめる。
