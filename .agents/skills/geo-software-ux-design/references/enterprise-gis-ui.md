# 業務・行政 GIS 固有の UI / UX 設計

一般向けの閲覧地図と異なり、業務用・自治体向け GIS では「地図を見ながら台帳を扱う・編集する・帳票に出す・現地で記録する」作業が主役になる。以下の 6 つのパターンから必要なものを設計し、`product-brief.md` の「画面と操作」に書く。

## 1. 属性テーブルと地図の双方向連動

- **選択の同期**: 地図上で地物をクリックしたら属性テーブルの該当行へスクロール・強調し、テーブルの行を選んだら地図を該当範囲へパン/ズームする。
- **フィルタの同期**: テーブルの列フィルタ・検索結果と地図上の表示地物を一致させ、「現在の絞り込み結果だけを CSV / GeoJSON で出力する」ボタンを置く。
- **大量行の描画**: 1,000 件を超えるテーブルは仮想スクロール (virtual scroll) を使い、DOM 肥大で地図操作が重くならないようにする。

## 2. 作図・ジオメトリ編集と排他制御

- **編集ツール**: 点・線・ポリゴンの新規作成、頂点移動、ポリゴン分割/結合、既存地物へのスナップ (snapping) が要るかを決める。
- **Undo / Redo と下書き**: 編集中の誤操作を戻せるようにし、確定保存前にバリデーション (自己交差、トポロジー破綻、必須属性欠落) を行う。
- **排他ロック・楽観ロック**: 複数職員が同時に同じ台帳地物を編集する場合、更新時刻や版番号 (`etag` / `version`) による楽観ロックを掛け、競合時は上書きせず差分を見せる。編集履歴 (誰がいつ変えたか) を残す。

## 3. 距離・面積計測

- 2 点間・折れ線の距離と、多角形の面積を測る計測モードを設ける。
- **測地計算**: メルカトル投影 (Web Mercator) 上の図上距離ではなく、回転楕円体上の測地距離・測地面積 (例: Turf.js の `length` / `area` や地理院の計算式) を使い、単位 (m / km、m2 / ha) を明記する。

## 4. 定型帳票・高解像度印刷 (PDF / A3 / A4)

- 窓口配布や決裁資料では「画面のスクリーンショット」ではなく、**用紙サイズ (A4/A3 縦横)・縮尺 (例: 1/2,500)・タイトル・凡例・方位記号・作成日・帰属表示** を含む定型レイアウトで出力できることが求められる。
- **実装方式の選択**:
  - ブラウザ印刷 (`@media print` + `canvas.toDataURL()` 埋め込み): 軽いが、WebGL キャンバスは `preserveDrawingBuffer: true` や印刷時の再描画、タイル読み込み完了待ちが要る。
  - サーバー側 PDF 生成 (Playwright / Headless Chromium / 静的画像合成): レイアウトと解像度が安定し、決裁用 PDF として再現性が高い。
- 商用タイルや地理院地図を印刷物に出す場合は、印刷・複製の利用規約 (`geo-software-legal-check`) を必ず確認する。

## 5. 現地調査のオフライン同期と競合解決

- 山間部や地下・災害現場向けの調査アプリでは、対象エリアのタイル・ベクタデータ・調査票を事前に端末へダウンロード (OPFS / IndexedDB / SQLite) できるようにする。
- 通信復帰時の同期は「サーバー優先」「端末優先」「競合リストで人が選ぶ」のどれかを決め、写真 (大容量バイナリ) は軽量なメタデータ同期と分離して再送可能にする。

## 6. 自治体のアクセシビリティ要件 (JIS X 8341-3 達成等級 AA)

- 自治体公開サイトでは JIS X 8341-3 達成等級 AA (WCAG 2.1 AA 相当) が調達要件に入ることが多い。
- 地図キャンバス自体は操作が難しいため、**「同等の情報をテキスト一覧・検索・テーブルで完全に閲覧・検索できる代替経路」** を必ず用意し、キーボード操作順 (`Tab`)、フォーカス表示、色覚に頼らない凡例 (線種・パターン・ラベル併用)、コントラスト比 4.5:1 以上を満たす。
