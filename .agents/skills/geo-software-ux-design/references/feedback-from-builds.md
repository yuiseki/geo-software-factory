# 作ったものへの指摘から

地図アプリ 1 本を企画から公開まで通したとき、本人から受けた画面と操作への指摘を一般化したもの。昼の擦り合わせで先に聞いておくか、夜に迷ったときの既定にする。

## 部品と導線

- 新しい部品を作る前に、既存の部品を使い回す。ページごとに別々の見出しや戻る導線を作ると、グローバルナビゲーションとトーンが崩れる。1 つのヘッダーを全ページに置き、そこに現在地 (パンくず) とアカウントの操作を載せる。
- 同じ見た目の部品は、どのページでも同じ所へ行く。サイト名を押したときの行き先がページによって違うと混乱する。
- アカウントのメニューに足せるなら、そこに自分のページへの導線を入れる (認証の SDK のメニューは項目を足せることが多い)。
- 見出しが折り返しても、ボタンが潰れないようにする (ボタンは縮めない、文字は折り返さない)。

## 地図

- 地図のプロダクトでは、最初に開く画面を地図にする。地図のカードを押して一覧が出ると戸惑う。
- 現在地はライブラリ標準のコントロールを使う。状態が色で出るなど、作り直すより良いことが多い。
- 初めの表示範囲は場面で変える。使っている最中は現在地と対象、振り返るときは対象だけ。
- 小さな地図のカードは操作を無効にし、収める範囲に余白を取る。
- 状態は色と記号の両方で出す (解除済みは緑のマーカーと ✅)。一覧では記号を行の先頭に置き、縦に揃える。

## 書けない人への見せ方

- 書き込めない人 (ログインしていない人) には、操作を隠さず無効にして見せる。何ができるサービスかが伝わる。
- 書けない人に意味の無い絞り込みは無効にし、既定を「全部見える」側にする。既定で空のページを見せない。
- 一時的に閉じている機能 (準備中のログインなど) は、無効にしたうえで理由を出す。無効にしたボタンの標準のツールチップは、環境によってカーソルの印に隠れて読めないので、ホバーで出す自前の吹き出しにし、ボタンの横 (画面の内側) に出す。タッチの端末ではホバーが残らないように、ホバーを持つ端末だけに当てる。
- 計画中のものなど、本人にだけ見せるものは、画面で隠すだけでなくサーバーの読み出しで除く。
