## 概要

アドレス・ベース・レジストリ (ABR) は、住所・所在地の公的な基礎データベース (法律上の名称は「公的基礎情報データベース」) である。都道府県、市区町村、町字、住居表示 (街区、住居)、地番のマスターと、それぞれに代表点などの位置を付けた「位置参照拡張」を CSV で配っている。元データは電子国土基本図 (地名情報、国土地理院)、位置参照情報 (国土交通省)、登記所備付地図データ (法務省) などである。デジタル庁は町字 (文字情報) を 2025-06-01 に正式版として公開しており、住居表示と地番は政策ページ上では「未整備」で整備方針を検討中としている。

## 形式と取得方法

- 配布形式 (Shapefile、GeoJSON、GeoParquet、PMTiles、CSV など): ZIP で圧縮した CSV (UTF-8)。列名は英字の略語 (`lg_code`、`machiaza_id`、`rep_lon` など)。町字マスターには漢字、カナ、ローマ字の表記、住居表示か否か (`rsdt_addr_flg`)、施行日・廃止日などがある。
- 取得方法 (一括ダウンロード、API、範囲を絞った取得): ファイルの一括ダウンロード。全国、都道府県、市区町村の単位でファイルが分かれる (例: `mt_town/city/mt_town_city131016.csv.zip`)。データの一覧は ArcGIS Hub の検索 API で取れる。住所の正規化とジオコーディングには、デジタル庁が MIT ライセンスで公開する abr-geocoder (最新リリース 3.0.52、2026-10-05 公開) がある。既定ブランチの README では、全国データや住居表示・地番を使うには PostgreSQL に取り込んでから DuckDB のキャッシュを作る構成になっている。
- 座標参照系: 位置参照拡張の各行に `rep_srid` で書かれる。住居表示と地番は `EPSG:6668` (JGD2011 の緯度経度)。千代田区の町字の代表点は 140 行のうち 136 行が `EPSG:4612` (JGD2000)、4 行が `EPSG:6668` で混在していた。

## ライセンスと出典表示

- ライセンス: 利用規約は PDL1.0 を適用すると書く。ダウンロードサイトのメタデータは CC BY 4.0 と表示する。PDL1.0 は 1.7.3 で CC BY 4.0 と互換で、CC BY に従った利用も許諾するとしている。地番系の 2 データは登記所備付地図データ利用規約も重なる。
- 出典表示の書き方 (公式の例): 利用規約の例は「出典：「○○動向調査」（デジタル庁）（当該ページの URL）」。PDL1.0 の基本形は「出典：D 庁ウェブサイト（当該ページの URL）、PDL1.0（規約原文ページの URL）」。ABR の具体的な文例 (データ名の書き方) は公式には見当たらなかった。
- 加工したときの表示: 出典とは別に、加工したことと加工した主体を書く (例:「「○○動向調査」（デジタル庁）（URL）を加工して作成」)。加工した情報を国が作った未加工の情報であるかのように公表してはならない。
- 商用利用、再配布、加工したものの再配布: PDL1.0 は出典表示などの条件のもとで複製、公衆送信、翻訳・変形などの翻案を認め、商用利用も認める。第三者の権利が含まれる場合は利用者が許諾を得る (PDL1.0 1.2)。地番系は登記所備付地図データ利用規約の条件も満たす必要がある (その内容は本調査では読んでいない)。
- 他のデータと混ぜたとき (ODbL、CC BY、PDL、政府標準利用規約など) の条件: PDL1.0 と CC BY 4.0 は互換と明記されている。ODbL との関係は公式の記述がない。OSMF は CC BY 系のデータを OSM に取り込むには明示の許諾が要るとしており、PDL1.0 についての判断は確認できなかった。ABR を OSM 本体に取り込むことは、許諾なしにはできないと考えられる (推測)。OSM と同じ地図に並べるときの条件は `../license-mixing.md`。

## 品質の限界

- 位置は代表点が中心で、町字や地番の区域の形 (ポリゴン) は、少なくとも千代田区の例では入っていない。
- 位置参照拡張の座標系が行ごとに JGD2000 と JGD2011 で混在する例がある。読むときに `rep_srid` を見て変換しないと、数十 cm 程度のずれや、東日本大震災で地殻変動の大きかった地域ではより大きなずれが出る可能性がある (推測)。
- 縮尺 `rep_scale` は 500 から 25000 まで違い、精度はデータの種類と出所で大きく変わる。
- 更新は自治体からの情報に依存し、データの種類や市区町村で最終更新日がばらばら (例: 住居表示は 2025-10、町字は 2026-11)。
- 住居表示と地番は政策ページでは「未整備」とされ、配っているデータが正式版と同じ扱いかは明記がない。
- 旧データカタログ (`catalog.registries.digital.go.jp`) は確認時点で名前解決できなかった。旧 URL を前提にしたツールは取得に失敗する。

## 地図プロダクトでの使いどころ

- 住所の文字列を正規化し、町字 ID などの公的な ID と結びつけるとき (abr-geocoder を使う、あるいは町字マスターで自前の辞書を作る)。
- 住所から代表点を引いて地図に点を置くとき (住居表示地区は住居単位、それ以外は地番か町字単位)。
- 町字の新設、廃止、名称変更を追いたいとき (施行日・廃止日の列がある)。
- 公共案件で、公的な出所であることが求められる住所データ。

## 向いていない場面

- 町字や地番の区域ポリゴンを地図に塗り分ける場面 (ポリゴンが入っていない例が多い。区域ポリゴンは別のデータを探す必要がある)。
- 精度の揃った位置が要る場面 (縮尺がデータの種類で 500〜25000 と違う)。
- 日本以外を含むプロダクトの住所データ。
- 毎日の更新を前提にする場面 (更新周期が決まっていない)。
