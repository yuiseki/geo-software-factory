対象: 気象庁が公開する気象・地震・津波のデータ (防災情報 XML、アメダス、降水ナウキャストなどのタイル、警報・注意報、地震情報) と、その利用条件と気象業務法の制約

## 概要

気象庁のデータは、公式に配布を案内しているもの (防災情報 XML、アメダスや過去の気象データの CSV、GPV のサンプル、予報区の GIS データ) と、気象庁ホームページの画面が内部で読んでいる JSON やタイル (`https://www.jma.go.jp/bosai/` の下) の 2 種類に分かれる。地図サービスが「気象庁の雨雲」や「アメダス」を重ねるとき、多くは後者を直接読んでいる (推測。2026-11-11 の観察で、千葉の風水害アーカイブ Ri2MAPS が www.jma.go.jp のデータを重ねていた)。後者は仕様が公開されておらず、予告なく変わる。利用条件は両方とも気象庁ホームページの利用規約にかかり、商用利用はできるが、出典と加工の表示が要り、予報や警報の中身を変えて出すと気象業務法にかかる。

## 形式と取得方法

- 防災情報 XML: Atom フィードで更新を知り、個々の XML 電文を取りに行く。1 日に 10GB 以上のダウンロードがあると、アクセス元の IP アドレスが遮断される。取得済みのファイルを取り直さない作りにする (https://xml.kishou.go.jp/xmlpull.html)。
- 画面の JSON とタイル: ブラウザの開発者ツールで見える URL を直接読む形になる。「ご利用上の留意事項」は「コンテンツは予告なく変更、移転、削除等が行われることがあります」と書いている。上の警報の JSON のように、URL が 200 を返したまま中身だけが古くなることがある。読むなら、応答の発表時刻 (`reportDatetime` など) と last-modified を見て、古ければ地図に出さない作りにする (推奨)。
- 確実な配信: 留意事項と防災情報 XML のページは、迅速かつ確実な配信が要るなら気象業務支援センターや予報業務許可事業者に問い合わせるよう案内している。
- 座標参照系: 画面のタイルは Web メルカトルの XYZ と同じ番号の振り方で読める (実測、z=6 のタイルで確認)。防災情報 XML の座標系の詳細は本調査では読んでいない。

## ライセンスと出典表示

- 商用利用: 留意事項の 2 ① は「気象業務法の趣旨に反しない限り、原則として制限はありません。商用利用も可能です」と書く。利用規約は PDL1.0 に準拠した条件とする。
- 出典: 利用規約の文例は「出典：気象庁ホームページ（当該ページの URL）」、図や写真は「『図・写真等の名称』（気象庁ホームページより）」。
- 加工: 出典とは別に、編集・加工したことを書く。文例は「気象庁『図・写真等の名称』（当該ページの URL）を加工して作成」。留意事項は、編集責任が編集者にあることも書くよう求める。加工した情報を国が作ったように見せてはならない。
- 適用外: 気象庁のロゴやシンボルマーク、別の利用ルールを示したコンテンツ。
- 免責: 利用者がコンテンツを使って行う一切の行為について気象庁は責任を負わない、と利用規約と留意事項の両方が書く。

## 気象業務法の制約

条文 (e-Gov 法令検索、気象業務法):

- 第 2 条第 6 項: 「この法律において「予報」とは、観測の成果に基づく現象の予想の発表をいう。」第 7 項: 「「警報」とは、重大な災害の起こるおそれのある旨を警告して行う予報をいう。」
- 第 17 条第 1 項: 「気象庁以外の者が気象、地象、津波、高潮、波浪又は洪水の予報の業務（以下「予報業務」という。）を行おうとする場合は、気象庁長官の許可を受けなければならない。」
- 第 23 条: 「気象庁以外の者は、気象、地象、津波、高潮、波浪及び洪水の警報をしてはならない。ただし、政令で定める場合は、この限りでない。」

気象庁の説明 (留意事項と「気象等の予報業務許可についてよくある質問と回答」):

- 公開 XML 電文の予報の値や対象区域を別の値や区域に変えて他者に繰り返し提供すること、観測資料に基づいた独自の予想を他者に繰り返し提供することは、独自の予報をする業務に当たる (留意事項 3 ①)。
- 公開 XML 電文の本質を損なうような編集は認められない (留意事項 3 ②、第 23 条)。
- 予報を解説するだけなら許可は不要。GPV をそのまま提供、表示することは許可なしでできるが、空間内挿や高度の補正を加える、格子の値を「特定地点の予報」として示すと独自の予報とみなされる。GPV を出すときは数値予報モデルの結果であることと、大きな誤差を含みうることを示すよう勧めている。
- 一般的な警戒の呼びかけは警報に当たらない。時と場所を具体的に示すと独自の警報と解釈されうるが、気象庁の警報と整合していれば独自の警報とはみなされない。

地図プロダクトへの読み (推測。法的な判断ではない):

- 気象庁が発表した警報や観測値を、区域と中身を変えずに地図に塗るのは、上の説明の「そのまま提供、表示」に近い。
- ナウキャストのタイルを別の格子に補間する、市区町村の境界で切り直して「この町の予報」として出す、機械学習で雨の先行きを予想して出すのは、独自の予報や区域の変更に当たりうる。設計に入る前に、気象庁の予報業務許可の窓口に相談する。
- 警報の区域を地図の塗り分けにするとき、塗る単位 (市町村など) を気象庁の発表単位からずらさない。

## 地図プロダクトでの使いどころ

- 防災の地図で、警報・注意報、地震、津波の発表をそのまま重ねたいとき。公式に案内のある防災情報 XML を使う。
- 雨雲 (ナウキャスト) やアメダスを重ねたいとき。公式に配布しているのはアメダスの CSV までで、ナウキャストのタイルは画面のデータを読む形になる。止まったり変わったりしても壊れない作り (時刻の確認、取得失敗の表示) にする。

## 向いていない場面

- 止まると困る業務の配信。気象庁は配信の停止や遅延がありうると書いており、確実な配信は気象業務支援センターや予報業務許可事業者を案内している。
- 気象庁の発表を加工して独自の予想を出すこと (予報業務許可が要りうる)。
